    综合项目:UART 收发器

    前面九课的东西在这一课里全部上场:计数器分频、状态机、移位寄存器、异步输入同步、边沿检测、参数化。UART 是最值得亲手写一遍的协议 —— 简单到能完全想清楚,又真实到能插上电脑就用。

    学完这一课你能
    说清一帧 UART 数据的每一位是什么,以及为什么低位先发
    把波特率换算成分频比,并判断误差能不能接受
    写出发送器和接收器,解释接收端为什么要在每一位的中点采样
    用回环 Testbench 自己验证自己,包括故意注入一帧坏数据

    本课路线

      一帧长什么样

      UART 没有时钟线,两边只靠“事先约好的波特率”对齐。所以一帧的格式必须严格固定:空闲时线是高电平,一个下降沿宣布数据开始。

      波特率就是一个分频比

      波特率 9600 的意思是每秒 9600 位,也就是每位 1/9600 秒。在 50MHz 时钟下,一位需要数多少个时钟?DIV = 时钟频率 / 波特率,就这么简单。

      50MHz 时钟下的分频比
      波特率DIV(取整)每位时长取整误差
      96005208104.2 µs0.006%
      19200260452.1 µs0.006%
      1152004348.68 µs0.008%
      921600541.085 µs0.46%
      误差能容忍多少

      接收端在起始位的中点对齐,之后每隔一位采样一次。到最后的停止位时,已经过去了 9.5 个位宽。要让采样点还留在那一位里面,累计偏移必须小于半个位宽:

      9.5 × 每位误差 < 0.5   →   每位误差 < 5.3%

      这是理论上限。实际上对方的时钟也有误差,双方各分一半,再留点余量 —— 工程上按 ±2% 以内来要求。表里最差的 0.46% 完全没问题。

      发送器

      发送端不需要采样,只要按节拍把十位依次推到线上。用一个 bit_idx 记录“现在发第几位”,一个分频计数器决定“什么时候该换下一位”。

      • 复位时 tx <= 1'b1。这是必须的:空闲电平是高,复位时给成 0 相当于在线上放了一个永久的起始位,对方会一直收到乱码。
      • shifter[0] 配合右移,天然实现“低位先发”。这就是第 03 课练习二那个移位寄存器。
      • busy 让上层知道“现在不能给新数据”。接口一定要有这个信号,否则上层只能靠数时钟猜。

      接收器:为什么非要在中点采样

      接收端唯一的时间基准是那个起始位的下降沿。如果检测到下降沿就立刻开始每隔 DIV 个时钟采一次,采样点会正好落在每一位的边界上 —— 那是信号正在跳变、最不确定的地方,而且只要两边波特率有一点点误差,立刻采错。

      解法只有一句:先等半个位宽。之后每隔一整位采一次,采样点就永远落在每一位的正中间,左右各有半个位宽的容错余量 —— 这正是上面那 5.3% 误差预算的来源。

      接收器里的四个设计决定
      做法为什么
      采样用 rx_d1 而不是 rxrx 是异步的,直接采会有亚稳态风险(第 06 课)。rx_d1 已经同步过两拍
      起始位中点再确认一次低电平线上的一个窄毛刺也会产生下降沿。中点还是低才算真的起始位,这一步挡掉了大部分干扰
      停止位不对时报 frame_err说明波特率不匹配或线上有干扰。不要把这一帧当好数据交出去
      valid / frame_err 在块开头置 0第 06 课练习三那个技巧:默认值加某分支拉高,自动就是单周期脉冲
      同步链的延迟会吃掉一点余量

      三级触发器让检测到的下降沿比真实沿晚 2–3 个时钟,采样点也就整体右移了 2–3 个时钟。DIV = 434 时这可以忽略;但如果你把 DIV 压到 4,固定偏移已经接近半个位宽,采样点会贴到每一位的末尾。

      所以仿真时压缩 DIV 要留分寸:DIV ≥ 16 既能让仿真跑得快,又保留了足够的中点余量。本课的 TB 用的就是 16。

      回环测试:让它自己验自己

      把 tx 直接接到 rx,发出去的字节应该原样收回来。这种回环测试的好处是不需要写参考模型 —— 发的就是期望值。

      测试向量选的是 55 AA 00 FF —— 交替、反交替、全零、全一。这四个能抓出绝大多数位序错误和边界问题:如果你把 LSB/MSB 搞反了,55 收回来会变成 AA;如果多算或少算了一位,00 和 FF 会立刻露馅。

      .\sim.bat lesson10 uart_loop_tb
[TB] DIV=16,回环发送 4 个字节:55 AA 00 FF
[TB] 3270 ns 第 0 字节收到 55  [PASS]
[TB] 6830 ns 第 1 字节收到 aa  [PASS]
[TB] 10390 ns 第 2 字节收到 00  [PASS]
[TB] 13950 ns 第 3 字节收到 ff  [PASS]
[TB] 注入一帧停止位错误的数据,应该报 frame_err 而不是 valid
[TB] 17470 ns 正确检出帧错误  [PASS]
[结果] UART 回环与帧错误检测全部通过

      (时间戳取决于 DIV 和帧间空隙,你跑出来的数值会不同,重要的是四个 PASS 和最后那个帧错误。)

      波形上该看哪三行

      line(串口线)、u_rx.bit_idx、u_rx.shifter。把 line 拉宽到能看清十位,然后对着 bit_idx 数:它应该从 0 走到 9,并且每次变化都发生在 line 上某一位的中间而不是边界。这是确认中点采样真的生效的唯一办法,看输出对不对是不够的 —— 采样点贴在边界上时,理想仿真里照样能收对。

      上板之前的六件事

      1. 电平。FPGA 引脚是 3.3V LVCMOS,常见的 USB-TTL 串口模块也是 3.3V,可以直连。不要直接接 DB9 的 RS-232 —— 那是 ±12V,会烧掉引脚,必须过 MAX3232 之类的电平转换。
      2. 接线交叉。你的 tx 接对方的 RX,你的 rx 接对方的 TX。两边 TX 接一起是最常见的“完全没反应”原因。
      3. 共地。GND 必须连,否则电平没有参考点,现象是收到随机乱码。
      4. 参数一致。上位机(串口助手 / PuTTY)的波特率、8 位数据、1 位停止位、无校验,四项都要和你的设计对上。
      5. 把 DIV 改回真值。仿真用的 16 留在代码里,上板后波特率会是 3Mbps 以上,对方完全收不到。这是最容易忘的一步。
      6. 引脚约束。Vivado 写 XDC(set_property PACKAGE_PIN … [get_ports tx]),Quartus 写 QSF 或用 Pin Planner。约束错了编译照样通过,只是信号出现在别的引脚上。
      第一次上板的调试顺序

      先只做发送:每秒往外发一个固定字节,用串口助手看能不能收到。收到了,说明时钟频率、DIV、引脚、电平、接线全部正确 —— 一次验证掉五件事。然后再做接收。

      反过来先做接收会很难查:收不到时你分不清是自己的接收器错了,还是线接错了,还是波特率不对。永远先让最简单的那条通路跑通。

      练习

      1. 把 DIV 压到 8 和 4热身

        把 uart_loop_tb.v 的 DIV 依次改成 8 和 4 重跑。数据还对吗?打开波形,量一量 u_rx 采样的那一刻落在每一位的什么位置。

        参考答案

        两种情况下数据大概率仍然全对 —— 但这正是这道题的陷阱:结果对不代表设计健康。

        量一下采样点:DIV=16 时落在每一位偏后一点的位置,离两边都还有五六个时钟;DIV=8 时挪到接近后 1/4;DIV=4 时几乎贴在每一位的最后一个时钟上。偏移量是固定的 2–3 个时钟(同步链的延迟),DIV 越小,它占的比例越大。

        在理想的仿真回环里,贴边也能采对,因为线上没有任何抖动、两边分频比一模一样。真实链路上有传输延迟、上升沿斜率、双方晶振误差 —— 贴边就等于随机出错。

        教训:仿真通过不等于设计有余量。压缩参数加速仿真时,要清楚自己压掉的是什么;像这里,压掉的就是采样余量。

      2. 加上奇偶校验位动手

        给 uart_tx 和 uart_rx 各加一个参数 PARITY(0=无, 1=奇, 2=偶)。有校验时一帧变成 11 位,接收端校验不过要输出 parity_err。

        参考答案

        发送端把 bit_idx 的上限从 9 改成 10,在数据位之后插入校验位:

        localparam LAST = (PARITY == 0) ? 4'd9 : 4'd10;
wire par_bit = (PARITY == 1) ? ~(^data)     // 奇校验:凑成奇数个 1
                             :  (^data);    // 偶校验:凑成偶数个 1

// XMIT 里改成:
if (bit_idx == LAST) begin … 回到 IDLE … end
else begin
    bit_idx <= bit_idx + 1'b1;
    if (bit_idx <= 4'd7)                    tx <= shifter[0];
    else if (bit_idx == 4'd8 && PARITY != 0) tx <= par_bit;
    else                                     tx <= 1'b1;   // 停止位
end

        接收端在 bit_idx 走到校验位时把收到的位存下来,和自己算的比对:

        4'd9: if (PARITY != 0) begin
          par_rx  <= rx_d1;
          bit_idx <= 4'd10;
      end else begin … 当停止位处理 … end

4'd10: begin
    state <= IDLE;
    if (!rx_d1)                       frame_err  <= 1'b1;
    else if (par_rx != exp_parity)    parity_err <= 1'b1;
    else begin data <= shifter; valid <= 1'b1; end
end

        其中 exp_parity 用 ^shifter 算(第 02 课练习一的归约异或)。

        注意 PARITY == 0 那些分支:用参数做的判断在综合时就定了,不会留下多余电路 —— 这正是第 08 课的 generate if 思路,只不过这里写在 always 里,工具照样能常量折叠掉。

      3. 给发送端加一个 FIFO动手

        把第 09 课的 sync_fifo.v 拷到 lesson10/,写一个 uart_tx_fifo.v:上层往 FIFO 里连续塞字节,模块自己一个一个发出去。上层只需要看 fifo_full。

        参考答案
        module uart_tx_fifo #(
    parameter DIV   = 434,
    parameter DEPTH = 16
)(
    input  wire       clk,
    input  wire       rst_n,
    input  wire       wr_en,          // 上层写入一个字节
    input  wire [7:0] wr_data,
    output wire       fifo_full,
    output wire       tx
);
    wire       empty, tx_busy;
    wire [7:0] fifo_dout;

    // FIFO 里有货、发送器又空闲 → 取一个出来发
    wire pop = ~empty & ~tx_busy;

    sync_fifo #(.W(8), .DEPTH(DEPTH)) u_fifo (
        .clk(clk), .rst_n(rst_n),
        .wr_en(wr_en), .din(wr_data),
        .rd_en(pop),   .dout(fifo_dout),
        .full(fifo_full), .empty(empty), .count()
    );

    uart_tx #(.DIV(DIV)) u_tx (
        .clk(clk), .rst_n(rst_n),
        .start(pop), .data(fifo_dout),
        .tx(tx), .busy(tx_busy)
    );
endmodule

        pop 同时当 FIFO 的 rd_en 和发送器的 start,这一点值得想清楚:在 pop 为高的那个时钟沿,发送器锁存 fifo_dout(组合读,正是队头),FIFO 的读指针同时前移。下一拍 tx_busy 变高,pop 自动落下 —— 一个信号既是握手也是脉冲,不需要额外状态机。

        加了 FIFO 之后上层就自由了:一次塞十几个字节走人,不用再盯着 busy 一个一个喂。这是所有串行外设的标准做法。

      4. 对方波特率偏 3%,先坏哪一位想清楚

        假设你的接收器分频比准确,但对方的发送波特率偏高 3%。第几位数据最先采错?如果双方各偏 3%(方向相反)呢?

        参考答案

        接收端在起始位中点对齐,之后第 n 次采样落在距起始沿 (n + 0.5) 个接收端位宽处。误差 e 让这个位置相对发送端偏移 (n + 0.5) × e 个位宽。采样点要留在那一位里,就得满足:

        (n + 0.5) × e < 0.5

        n 最大是 9(停止位),所以最先出错的一定是停止位 —— 它离对齐点最远,累计偏移最大。这也解释了为什么 frame_err 是波特率不匹配最灵敏的症状:数据可能全对,停止位先崩。

        • 单边 3%:9.5 × 3% = 0.285 个位宽 < 0.5,还能收对,但余量只剩 21%。
        • 双方各偏 3%、方向相反:相对误差 6%,9.5 × 6% = 0.57 > 0.5 —— 停止位采到了下一位的位置,frame_err 报错。数据位 D7 的偏移是 8.5 × 6% = 0.51,也已经出界,所以实际上最后两位一起坏。

        这就是 ±2% 这条工程经验的来历:给双方各留 2%,相对误差 4%,最坏偏移 9.5 × 4% = 0.38 个位宽,再扣掉同步链偏移和线上抖动,刚好还有余量。

      往后走

      到这里,同步数字设计的基本功已经齐了:组合与时序、状态机、存储、跨时钟同步、参数化复用,以及最重要的那件事 —— 写完就仿真,看波形而不是猜。

      紧接着有一节加餐:第 11 课 · 读懂时序图 —— 前十一课的接口都是你自己定的,那一课教你怎么读别人家芯片的数据手册,并把一张 SDRAM 时序图翻译成状态机。再往后这几条路都值得走:

      • 时序约束与收敛。学会写 XDC/SDC,读时序报告,理解建立/保持时间、时钟偏斜、多周期路径。这是从“功能对”到“能跑在 200MHz”的分水岭。
      • 跨时钟域进阶。异步 FIFO、握手协议、格雷码指针 —— 第 06 课和第 09 课已经埋好了全部零件。
      • 标准接口。AXI4-Stream 是 FPGA 世界的通用语言,而它本质上就是 valid / ready 两根线的握手。学会它,厂商 IP 就都能接起来。
      • SystemVerilog 与验证。logic、always_ff、typedef enum 先用起来;再往后是断言(SVA)和约束随机验证。
      • 买一块板子。前十课不需要板子,但“代码变成会亮的灯”这件事对坚持下去的帮助超出想象。
