    Lesson 09 ／ 片上存储

    存储器:RAM、ROM 与 FIFO

    FPGA 里有成百上千个独立的块 RAM,它们是这颗芯片最值钱的资源之一。而你调用它们的方式简单到令人意外:声明一个二维数组,在时钟块里读写它。这一课把三件事讲清楚 —— 数组怎么变成块 RAM、$readmemh 怎么把数据装进 ROM、FIFO 的空满判断为什么需要多一位指针。

    学完这一课你能
    写出会被正确推断成块 RAM 的代码,并说清同步读为什么必然晚一拍
    用 $readmemh 初始化查表 ROM,并绕开路径相对性的坑
    实现同步 FIFO,解释“指针多一位”如何区分空和满
    知道块 RAM、分布式 RAM、纯寄存器三者该在什么时候用

    本课路线

      一个数组,三种实现

      reg [7:0] mem [0:255]; 这一行声明了 256 个 8 位存储单元。它最终变成什么,取决于你怎么访问它:

      三种片上存储资源
      实现什么写法会推断出它容量读延迟适合
      块 RAM(BRAM)读也在时钟块里(同步读),端口数 ≤ 2大,每块几 KB 到几十 KB1 拍(或 2 拍)几百字节以上的缓冲、帧存、查表
      分布式 RAM(LUT RAM)assign dout = mem[addr];(组合读)小,几十到几百比特0 拍浅 FIFO、小寄存器堆
      纯触发器整个数组同时被读写,或者有复位非常小0 拍十几个以内的寄存器
      块 RAM 不能复位

      如果你写 if (!rst_n) for (…) mem[k] <= 0;,综合工具会发现“这个存储必须能被整体清零”,而块 RAM 硬件做不到 —— 于是它放弃块 RAM,改用几百个触发器实现。资源报告上会看到触发器数量暴涨、BRAM 用量为 0。

      正确做法:存储阵列不复位。数据的有效性靠别的机制保证 —— FIFO 用指针,帧存用“写过才读”。要初始内容就用 $readmemh,那是块 RAM 原生支持的。

      同步 RAM:读一定晚一拍

      ROM 与 $readmemh

      $readmemh 的路径是相对于“你在哪运行仿真”

      不是相对于 .v 文件所在目录。sim.bat 在 code\ 下运行 vvp,所以路径必须写成 "lesson09/sine.hex"。写成 "sine.hex" 会得到一句 WARNING: cannot open file,然后 ROM 全是 x —— 而 $readmemh 找不到文件不会让仿真失败,它只是警告。

      两个应对办法:把路径做成 parameter,由顶层或 TB 传进来(本课的做法);或者在 Testbench 里额外检查一下第一个单元不是 x,把这类静默失败变成显式报错。

      综合时也认这一招

      Vivado 和 Quartus 都支持从 $readmemh 的 initial 块推断块 RAM 的初始内容,并把数据写进 bitstream。所以正弦表、字符点阵、系数表这类东西不需要专门用 IP 核生成 —— 一个 .hex 文件加三行代码就够。别忘了把 .hex 也加入工程文件列表,否则综合时找不到。

      同步 FIFO:多一位指针

      FIFO 的难点从来不是存储,是怎么判断空和满。用 DEPTH=8 举例:读写指针都是 3 位,写满一圈之后 wr_ptr 又转回 0,和 rd_ptr 相等 —— 可这时候是满,不是空。两种截然相反的状态,指针看起来完全一样。

      解法漂亮得像个魔术:给指针多加一位。这一位不参与寻址,只用来记“转了几圈”。

      • mem[wr_ptr[AW-1:0]] —— 寻址只用低 AW 位,多出来的最高位不参与。
      • do_wr = wr_en & ~full —— 把保护做在模块内部。这样调用者写满了也不会破坏数据,是好接口设计的标志。
      • count = wr_ptr - rd_ptr —— 指针回绕时这个减法照样正确,因为无符号减法本身就是模 2AW+1 运算。
      • DEPTH 必须是 2 的幂,否则指针自然回绕的周期和 DEPTH 不一致,空满判断全错。

      测存储器,要测的是边界

      “写进去能读出来”几乎不可能失败,测它没什么价值。真正会出错的是这四处:写满的那一刻、满了还写、读空的那一刻、空了还读。再加一条:指针回绕之后再走一圈 —— 很多 FIFO 的 bug 在第一圈完全正常,第二圈才暴露。

      在 GTKWave 里把 wr_ptr 和 rd_ptr 设成 Binary 显示,盯着最高位:写满一圈时它会翻一次,这就是“多一位”在工作的直接证据。

      异步 FIFO:第 06 课欠的那笔账

      第 06 课的结论是:两级同步器只对单比特有效,多比特总线各位可能采到不同拍,拼出一个从未存在过的数值。当时留了个话头 —— 多比特跨时钟域要用握手或异步 FIFO。现在把它补上。

      异步 FIFO 的读写用两个独立时钟,频率可以毫无关系。它靠三招做到安全:

      1. 指针用格雷码传过去。格雷码相邻两个值只差一位(第 08 课),所以对方同步时最坏情况也只是采到旧值或新值,不可能采到第三个值。二进制指针从 0111 跳到 1000 四位全翻,绝对不能直传。
      2. 指针多一位。和同步 FIFO 一样,用来区分空和满。
      3. 空满判断各在自己的时钟域里做。读侧判空、写侧判满,各自只需要对方那个同步过来的指针。而且判断结果必须寄存一拍,否则会形成组合环。
      三个非显然的细节
      写法为什么必须这样
      (bin >> 1) ^ bin二进制转格雷码的全部内容,就是第 08 课那一行 bin ^ (bin>>1)
      判断结果必须寄存否则 rempty → rbin_next → rgray_next → rempty 形成组合环,综合直接失败。用 *_next 算、寄存一拍输出,标志和指针才同拍生效
      满的条件是"最高两位取反"不是最高一位。格雷码里"多绕一圈"对应高两位同时反转 —— 拿 DEPTH=8 手算一遍:写 8 个后 wgray=1100、rgray=0000,正好符合
      格雷码只保证"读到的值是旧的或新的",不保证"是最新的"

      同步过来的指针天生落后 2 拍以上,所以 rempty 可能偏保守 —— 明明已经写进去了,读侧还以为是空的。wfull 同理会偏早报满。

      这是安全方向的误差,可以接受:保守判断只会少读几拍、少写几个,永远不会读到无效数据或覆盖未读数据。反过来如果误差朝另一个方向,那就是数据损坏。设计跨时钟域逻辑时,永远要确认误差偏在安全的那一侧。

      练习

      1. 把 ROM 的路径写错热身

        把 ram_rom_tb.v 里 .FILE("lesson09/sine.hex") 改成 .FILE("sine.hex"),重跑。发生了什么?终端里那句提示很容易被忽略,怎么让这种失败变得响亮?

        参考答案

        vvp 会打印一句 WARNING: … cannot open sine.hex,然后继续跑,ROM 内容全是 x,第 3 部分全部 FAIL。仿真没有失败退出,只是警告 —— 在几百行日志里极易漏掉。

        让它变响亮的办法:在模块的 initial 里加一句自检。

        initial begin
    $readmemh(FILE, mem);
    // synthesis translate_off
    if (mem[0] === {W{1'bx}}) begin
        $display("[致命] ROM 初始化文件没读到:%s", FILE);
        $finish;                     // 直接终止,不要带着一堆 x 往下跑
    end
    // synthesis translate_on
end

        这是一条通用原则:把静默失败改造成显式失败。仿真里最贵的时间都花在追查“为什么这里是 x”上,而 x 的源头往往就是某个没读到的文件、某个没接的端口。

      2. 双端口 RAM动手

        写 ram_dp.v:两个独立端口,A 口只写(wr_addr/din/we),B 口只读(rd_addr/dout),同一个时钟。写 TB 验证:同一拍写地址 5、读地址 5,读到的是新值还是旧值?

        参考答案
        module ram_dp #(
    parameter W     = 8,
    parameter DEPTH = 256,
    parameter AW    = $clog2(DEPTH)
)(
    input  wire          clk,
    input  wire          we,
    input  wire [AW-1:0] wr_addr,
    input  wire [W-1:0]  din,
    input  wire [AW-1:0] rd_addr,
    output reg  [W-1:0]  dout
);
    reg [W-1:0] mem [0:DEPTH-1];

    always @(posedge clk) begin
        if (we) mem[wr_addr] <= din;
    end

    always @(posedge clk) begin
        dout <= mem[rd_addr];
    end
endmodule

        读到的是旧值。因为两条 <= 都在同一个时钟沿执行,dout 取的是写入生效之前的内容。这个行为叫 READ_FIRST(读优先)。

        想读到新值(WRITE_FIRST),得自己在外面加旁路:

        wire same = we && (wr_addr == rd_addr);
reg  same_d, din_d;
always @(posedge clk) begin
    same_d <= same;
    din_d  <= din;
end
wire [W-1:0] dout_wf = same_d ? din_d : dout;   // 撞地址时直接用刚写的数

        不同工具、不同 RAM 原语的默认行为不一样,所以撞地址这件事永远要自己在 TB 里验一遍,不要假设。这是块 RAM 使用中最常见的一处“仿真和上板不一致”。

      3. 给 FIFO 加“将满”和“将空”动手

        给 sync_fifo 加两个输出:almost_full(还剩 MARGIN 个位置)和 almost_empty(只剩 MARGIN 个数据),MARGIN 做成参数。为什么真实系统里几乎必须有它们?

        参考答案
        parameter MARGIN = 2;
…
assign almost_full  = (count >= DEPTH - MARGIN);
assign almost_empty = (count <= MARGIN);

        为什么必须有:上游停不下来。full 拉高的那一拍才通知上游“别写了”,可上游收到这个信号需要一拍、它自己的流水线里可能还有两三拍的数据在路上 —— 等它真的停下来,FIFO 早就溢出了。

        所以正确的握手是用 almost_full 提前刹车,MARGIN 至少等于上游的反应延迟(拍数)。同理 almost_empty 用来提前唤醒上游补数据,避免下游断流。

        这就是为什么厂商 FIFO IP 都带一组可编程的阈值信号 —— 不是锦上添花,是能不能用的问题。

      4. DEPTH 不是 2 的幂会怎样想清楚

        把 sync_fifo_tb.v 的 DEPTH 改成 6,重跑。哪里开始不对?如果一定要支持任意深度,该怎么改?

        参考答案

        DEPTH=6 时 AW = $clog2(6) = 3,指针是 4 位。写 6 个之后 count = 6,full 正确拉高 —— 第一圈看起来没问题。问题出在回绕:指针加到 4'b1111 之后回到 0,而 16 不是 6 的整数倍,于是 count = wr_ptr - rd_ptr 从某一圈开始就和真实占用量脱节,空满判断全乱。

        要支持任意深度,得放弃“靠自然回绕”,改成显式管理:

        reg [AW-1:0] wr_ptr, rd_ptr;      // 回到 AW 位,不再多一位
reg [AW:0]   count;               // 单独维护占用量

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) wr_ptr <= 0;
    else if (do_wr)
        wr_ptr <= (wr_ptr == DEPTH-1) ? 0 : wr_ptr + 1'b1;   // 手动回绕
end
// rd_ptr 同理

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)                     count <= 0;
    else if (do_wr && !do_rd)       count <= count + 1'b1;
    else if (do_rd && !do_wr)       count <= count - 1'b1;
    // 同时读写:占用量不变
end

assign empty = (count == 0);
assign full  = (count == DEPTH);

        代价是多了一个计数器和两个比较器。所以工程上的默认选择很明确:能凑成 2 的幂就凑。要 6 个位置就做 8 个 —— 块 RAM 反正是按块分配的,多两个位置一分钱不花。
