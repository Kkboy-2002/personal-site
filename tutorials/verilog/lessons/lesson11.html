    读懂时序图:SDRAM 初始化

    前十一课的接口都是你自己定的。一旦要接一颗别人家的芯片,规则就由对方的数据手册说了算 —— 而手册说话的方式就是时序图。这一课拿 Micron 512Mb SDR SDRAM 的上电初始化当例子,把一张时序图从标签认起,一直读到能写出状态机、并让一个"假芯片"来判你对错。

    学完这一课你能
    认出时序图上七类标签,说清 tCK、tCH、tCMS、tRP 各自约束什么
    解释手册为什么必须画波浪线,以及你自己该怎么画不带波浪线的全量图
    把手册的 ns 值正确换算成时钟拍数(并且知道为什么只能向上取整)

    本课路线

      时序图上的七类标签

      一张手册时序图看着密,其实上面的东西只有七类。认清类别,剩下的就是查表。

      Figure 31 上出现的所有标签
      类别例子是什么
      ① 信号名(最左列)CK CKE COMMAND DQM A0–A9 A10 BA0,BA1 DQ芯片的引脚。COMMAND 不是真引脚,是 CS#/RAS#/CAS#/WE# 四根线的组合的简写
      ② 时刻标号(最上排)T0 T1 Tn+1 To+1 Tp+1第几个时钟上升沿。n/o/p 是没写死的数 —— 因为中间省略了很多拍
      ③ 时钟自身参数tCK tCH tCL周期 / 高电平宽度 / 低电平宽度。约束的是你的时钟源
      ④ 建立与保持(成对出现)tCKS/tCKH tCMS/tCMH tAS/tAH某根线相对时钟沿要提前多久稳定、之后要保持多久。约束的是你的输出
      ⑤ 命令间隔(图下方长箭头)tRP tRFC tMRD两条命令之间至少要隔多少时间。约束的是你的状态机
      ⑥ 命令名(框里的字)NOP PRECHARGE AUTO REFRESH LOAD MODE REGISTER ACTIVE那一拍发的是哪条命令
      ⑦ 图案与状态(右下图例)斜线 = DON'T CARE,网格 = UNDEFINED,High-Z斜线:这段随你给。网格:芯片输出不确定,别采。High-Z:总线没人驱动
      一个能立刻用上的分类法

      把标签按"约束谁"分三堆,一切就清楚了:③ 约束时钟源(选晶振/配 PLL);④ 约束你的输出(写 XDC 约束);⑤ 约束你的状态机(数拍子)。只有第 ⑤ 类会变成 Verilog 代码,前两类是别的环节的事。

      ③④ 两类:一个时钟沿上的全部参数

      这四个参数全都挤在同一个上升沿附近,画大了就一目了然。

      建立/保持不是"代码里等几拍"

      初学最容易把 ④ 和 ⑤ 混为一谈。tCMS = 1.5ns 不是让你在代码里等 1.5ns —— 你在 Verilog 里什么也做不了。它的意思是:当你的寄存器在某个沿输出命令、SDRAM 在下一个沿采样它时,这中间的一整个时钟周期减去 FPGA 的输出延迟、减去 PCB 走线延迟,剩下的余量必须还大于 1.5ns。这是时序约束和 PCB 的事,不是 RTL 的事。

      你在 RTL 里唯一要做对的,是把输出寄存起来(不要用组合逻辑直接驱动引脚),这样工具才有确定的起点去算这条路径。

      Figure 31 上每一列都有一对波浪线(≈),那是时间被剪断了的记号。为什么必须剪:

      tRP20 ns2
      tRFC66 ns7

      一万拍画不下,所以手册用波浪线把它压掉,时刻标号也只能写成 Tn+1、To+1 这种带未知数的形式 —— n、o、p 到底是几,取决于你的时钟频率,手册没法替你填。

      你自己画图时该怎么办:把参数压小

      这正是第 04 课那个技巧的又一次登场 —— 把时间相关的量全做成参数,画图和仿真时压到个位数。序列的形状一个字都不变,只是每段短了。下面这张图就是这么来的:上电等待压成 4 拍、tRP 压成 2 拍、tRFC 压成 3 拍、tMRD 压成 2 拍 —— 于是整个初始化 15 拍跑完,每一个时钟周期都能完整画出来,一根波浪线都不需要。

      全量时序图:15 拍,零省略

      横向可以滚动。每一根竖线就是一个真实的时钟上升沿,T0 到 T14 一拍不漏。

      逐拍读一遍

      T0 – T14 每一拍在干什么
      拍命令关键信号为什么
      T0NOPCKE=0时钟已稳定但 CKE 还压着 —— 芯片完全不看时钟,上电毛刺进不来
      T1NOPCKE=1 ↑把时钟放进内部。此后必须持续发空命令
      T2–T3NOP—凑满上电等待。真实设计这里是 10 000 拍
      T4PRECHARGE ALLA10=1上电后各 bank 行状态未知,一条命令全部推到 idle
      T5NOP—凑满 tRP。所有 bank 完成 precharge
      T6AUTO REFRESH—第 1 次。此时所有 bank 必须 idle,T4 已保证
      T7–T8NOP—凑满 tRFC
      T9AUTO REFRESH—第 2 次。手册要求至少两次,预热刷新计数器
      T10–T11NOP—凑满 tRFC
      T12LOAD MODE REGA=CODE
      BA=00      		写 CL / 突发长度 / 突发类型。配置借地址线传进去
      T13NOP—凑满 tMRD,让配置生效
      T14ACTIVEA=ROW
      BA=bank      		初始化结束,第一条真正的操作命令
      手册的三条 Notes 里有两条是干货
      • Note 1:mode register 可以提前到两次 AUTO REFRESH 之前加载。所以这个顺序不是唯一解,手册给了余地。
      • Note 2:CS# 在时钟高电平时为高,则一律当 NOP。所以状态机里"什么都不做"最省事的写法就是 cs_n = 1,其余三根线随便。
      • Note 3:tMRD —— Micron 自己写 2 个时钟,但 JEDEC 和 PC100 规范要求 3 个。保险起见按 3 拍写,多等一拍不花钱。

      mode register 里到底装了什么

      T12 那一拍送进地址线的 CODE,13 位每一段管一件事:

      为什么用地址线传:因为 LMR 这条命令不需要地址 —— 十几根地址线正好空着,拿来当配置总线用,省下十几个专用引脚。和 A10 在 PRECHARGE 里兼作 ALL 标志是同一个设计思路:命令用不上的引脚就复用。

      读手册的位域表时,先确认位序

      A6 A5 A4 装 CL,写成 010 表示 2。但"010 里哪一位是 A6"必须看清 —— 手册的表是 A6 在左。你在 Verilog 里写 addr[6:4] = 3'b010; 才对得上。反过来写就是 CL 配错,读数据全错位,而且编译和仿真都不报错。

      从时序图到状态机

      整套序列的形状是"发一条命令 → 等一段时间 → 再发下一条",这就是第 07 课交通灯的模式 —— 只是等待时长换成了手册里那几个 t 参数。

      三个值得注意的设计选择:

      • timeout || state != next_state 一起清计时器 —— 因为 S_REF 会自己跳回自己做第二次刷新,光判"换状态"清不掉。
      • first = (timer == 0) 让命令只在每个状态的第一拍发出,其余拍自动落回默认的 NOP。这样"发命令 + 等 t 参数"就压缩成一个状态,不用给每段等待再单独建状态。
      • limit 用一个组合 case 在几个 t 参数间选,比给每个状态各配一个计数器省得多 —— 和第 07 课交通灯选 T_GREEN/T_YELLOW 是同一招。
      这个模块的输出是组合逻辑 —— 真上板必须改

      为了让代码和上面那张时序图一拍对一拍,第三段写成了 always @(*)。但组合输出带毛刺,直接接到芯片引脚上,SDRAM 可能把毛刺采成命令。真实设计里这些输出必须寄存一拍,时序工具才有确定的起点去算 tCMS/tCMH。这是练习四。

      没有开发板,让"假芯片"判你对错

      前十一课的 Testbench 都是拿期望值比对输出。但初始化序列没有"输出"可比 —— 它的正确性在于命令的顺序和间隔。所以这一课换个打法:写一个行为模型,让它扮演 SDRAM,盯着命令流找违规。

      它检查五件事,每一件都对应手册的一条规定:

      行为模型的五项检查
      检查对应手册哪一条
      上电等待期内只许空命令步 4:"Wait at least 100µs prior to issuing any command other than COMMAND INHIBIT or NOP"
      PRECHARGE 后 tRP 内不许发别的命令步 7
      AUTO REFRESH 后 tRFC 内不许发别的命令步 9、步 11
      LMR 后 tMRD 内不许发别的命令步 13
      刷新不够 2 次、或 mode register 没写,就发 ACTIVE/READ/WRITE步 12 的"prior to applying any operational command"

      另外还查两条结构性的:AUTO REFRESH 时是否真的所有 bank 都 idle、LMR 时 BA 是否为 00。

      打印出来的拍号 4 / 6 / 9 / 12 / 14,和上面那张全量时序图上的 T4 / T6 / T9 / T12 / T14 完全对得上 —— 图、代码、仿真三者一致,这才算读懂了一张时序图。

      行为模型是外设开发的标准做法

      接任何一颗外部芯片(SDRAM、Flash、ADC、以太网 PHY),第一件事都不是写控制器,而是先写一个能挑错的行为模型。理由很实际:上板之后你只能看到"不工作",看不到"第 5 拍违反了 tRP"。厂家有时会提供官方的仿真模型(Micron 就提供 SDRAM 的 Verilog model),没有就自己写一个精简版 —— 哪怕只检查时序间隔,也能省掉几天的示波器时间。

      练习

      1. 把时序参数改错,看模型抓不抓得住热身

        把 sdram_init_tb.v 里传给 DUT 的 CYC_RFC 改成 2(模型那边仍然传 3),重跑。模型报什么?再把 DUT 的 REFRESH_CNT 改成 1 试试。

        参考答案

        CYC_RFC=2 时,状态机会在刷新后只等 2 拍就发下一条命令,模型立刻报:

        [模型] 第 8 拍  违规:距上一条 AUTO REFRESH 只过了 2 拍,至少要 3 拍

        REFRESH_CNT=1 时,只刷一次就去写 mode register,然后发 ACTIVE:

        [模型] 第 N 拍  违规:初始化没做完就发操作命令(刷新 1 次,mode 已写)

        这道题的意义在于确认测试真的有牙齿。写完检查器一定要故意破坏一次被检查的东西 —— 否则你不知道它是在放行还是压根没在看。这和第 06 课"把稳定时间改短,验证 key_down 不出现"是同一个动作。

      2. 把 ns 换算成拍数动手

        假设你用 -75 速度等级的片子,手册给 tRP = 20ns、tRFC = 66ns、tMRD = 2 个时钟,上电等待 100µs。分别算出 100MHz 和 133MHz 下该传什么参数,并写成能自动换算的形式。

        参考答案
        参数手册值100MHz(10ns)133MHz(7.5ns)
        上电等待100 µs10 00013 334
        tRP20 ns23
        tRFC66 ns79
        tMRD2 个时钟23 ①

        ① tMRD 手册写 2,但 JEDEC/PC100 要求 3 —— 按 3 填。

        133MHz 下 tRP 是 ceil(20/7.5) = ceil(2.67) = 3,不是 2。这就是"只能向上取整"的具体样子。

        写成自动换算,换频率不用重算:

        module sdram_init #(
    parameter CLK_MHZ    = 100,
    parameter T_RP_NS    = 20,
    parameter T_RFC_NS   = 66,
    parameter T_POWER_NS = 100_000,
    // 整数向上取整:(a*b + 999) / 1000
    parameter CYC_RP      = (T_RP_NS    * CLK_MHZ + 999) / 1000,
    parameter CYC_RFC     = (T_RFC_NS   * CLK_MHZ + 999) / 1000,
    parameter CYC_POWERUP = (T_POWER_NS * CLK_MHZ + 999) / 1000,
    parameter CYC_MRD     = 3
)(…);

        Verilog 里没有可综合的 ceil,(x + 999) / 1000 就是整数向上取整的标准写法。以后只改 CLK_MHZ,拍数自动跟着变。

      3. 加上周期性自动刷新动手

        初始化只是开头。SDRAM 的电容会漏电,必须每隔一段时间刷新一次,否则数据丢失。手册给的是 64ms / 8192 次。写一个 sdram_refresh.v:done 之后开始计时,每到期就请求一次刷新。

        参考答案

        先算间隔:8192 行要在 64ms 内全部刷完,所以平均每 7.8125µs 必须发一次 AUTO REFRESH。100MHz 下 = 781 拍。

        module sdram_refresh #(
    parameter CYC_REFI = 781        // 平均刷新间隔(拍)
)(
    input  wire clk,
    input  wire rst_n,
    input  wire init_done,
    input  wire ref_ack,            // 主状态机:这次刷新我受理了
    output reg  ref_req             // 到期了,请安排一次刷新
);
    reg [15:0] cnt;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            cnt     <= 16'd0;
            ref_req <= 1'b0;
        end else if (!init_done) begin
            cnt     <= 16'd0;
        end else begin
            if (ref_ack)                   ref_req <= 1'b0;   // 受理了就撤请求
            if (cnt == CYC_REFI - 1) begin
                cnt     <= 16'd0;
                ref_req <= 1'b1;                              // 到期,举手
            end else begin
                cnt <= cnt + 1'b1;
            end
        end
    end
endmodule

        两个关键设计:

        • 用请求/受理(req/ack)握手,而不是直接发命令。因为刷新到期时主状态机可能正在读写中间 —— 它得先把当前突发做完、把所有 bank PRECHARGE 掉,才能腾出手来刷新。第 06 课那个"事件用脉冲传、用寄存器记住"的模式,这里换成了 req 一直举着手直到 ack。
        • 计时器不因为 ack 晚来而重置。只要平均间隔守住就行 —— 手册允许你把几次刷新攒起来突发做掉,只要 64ms 内总数够 8192 次。

        顺带体会一下刷新的成本:每 781 拍就要中断一次正常访问,期间所有已打开的行全被关掉。这就是为什么 DRAM 的实际可用带宽总比标称值低几个百分点。

      4. 把输出寄存起来想清楚 + 动手

        把 sdram_init.v 的第三段从 always @(*) 改成时序块,让 cke/cmd/addr/ba 都寄存一拍。改完重跑,模型报的拍号会怎么变?为什么真实设计非改不可?

        参考答案

        改法:把第三段的 = 换成 <=、敏感列表换成时钟,并且判断条件要用 next_state 而不是 state(否则输出会比状态晚一拍,这是第 07 课第三段那个坑):

        always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        cke <= 1'b0;  cmd <= CMD_INHIBIT;
        addr <= 13'd0; ba <= 2'd0; done <= 1'b0;
    end else begin
        cke <= 1'b1;  cmd <= CMD_NOP;
        addr <= 13'd0; ba <= 2'd0; done <= 1'b0;
        // 用"下一拍会不会是某状态的第一拍"来决定这一拍输出什么
        …
    end
end

        所有命令的拍号会整体后移一拍(4/6/9/12 → 5/7/10/13),但相对间隔完全不变,所以模型的时序检查照样全过 —— 只有 TB 里那句"done 应在第 14 拍"要跟着改成 15。这本身是个好观察:时序约束管的是间隔,不是绝对时刻。

        为什么非改不可,三条理由:

        • 组合逻辑有毛刺。cmd 由 state 和 timer 译码而来,这些位不会同时到达,中间态可能短暂译出别的命令。芯片如果在那一瞬间采样,就执行了一条你没打算发的命令。
        • 时序分析需要确定的起点。tCMS/tCMH 是从"寄存器输出到 SDRAM 采样沿"算的。输出如果挂在一长串组合逻辑后面,这条路径的延迟由逻辑深度决定 —— 换个综合版本就变,根本没法约束。
        • 寄存的位置还要再往外推一层。真正上板时,这些信号还应该走 FPGA 的 IOB 寄存器(Vivado 里 set_property IOB TRUE),让触发器就坐在引脚旁边,输出延迟才最小、最确定。

        一句话:凡是要出芯片的信号,一律寄存,而且尽量寄存在 IOB 里。这条规矩对所有外部接口都成立,不只是 SDRAM。
