    Lesson 03 ／ 时序逻辑 ／ 本课最关键

    时序逻辑:always 与两种赋值

    前两课的电路没有记忆。这一课加进时钟,电路开始能记住上一拍发生了什么 —— 计数器、状态机、FIFO 全都建立在这一件事上。同时把新手第一号杀手解决掉:= 和 <= 到底差在哪一根波形上。

    学完这一课你能
    看一眼 always 块就知道它会综合出触发器还是纯组合逻辑
    说出同步复位与异步复位的真实差别,并在波形上指出来
    解释阻塞赋值为什么会把三级移位寄存器塌成一级

    本课路线

      时序逻辑 = 组合逻辑 + 一排触发器

      触发器只做一件事:在时钟上升沿的那一瞬间,把输入端的值抓住并保持到下一个沿。除此之外它不关心输入怎么抖。

      于是所有同步电路都是同一个形状:一堆组合逻辑算出“下一拍应该是什么”,一排触发器在时钟沿把它存下来,存下来的值又回头参与下一轮计算。always @(posedge clk) 里的每一个被赋值的信号,就是一个(或一组)触发器。

      两种 always,规矩完全不同

      时序:@(posedge clk) + <= 
      always @(posedge clk) begin
    if (!rst_n) cnt <= 8'd0;
    else        cnt <= cnt + 1'b1;
end

      综合出触发器。没写到的情况自动保持原值 —— 这正是我们要的“记忆”。

      组合:@(*) + = 
      always @(*) begin
    y = 1'b0;              // 先给默认值
    if (sel) y = a;
end

      综合出纯逻辑。每个分支都必须给所有输出赋值,否则会生成锁存器。

      两种 always 的对照
      组合 always @(*)时序 always @(posedge clk)
      赋值符= 阻塞<= 非阻塞
      综合结果LUT,没有存储触发器 + 它前面的 LUT
      分支没覆盖到出锁存器,是 bug保持原值,是特性
      信号声明reg(但不是寄存器)reg(真的是寄存器)
      能否代替 assign能,复杂条件下更好读不能,它多了一拍延迟
      一个信号只能在一个 always 里被赋值

      两个 always 块给同一个 reg 赋值,和两条 assign 驱动同一根 wire 是一样的错误。想在不同条件下改同一个信号,把这些条件写进同一个 always 块的 if/else 里。

      复位:同步还是异步

      差别只有一句话:异步复位不等时钟,同步复位要等时钟。平时看不出来,给一个比时钟周期还窄的复位脉冲就原形毕露。

      该用哪种
      异步复位同步复位
      响应速度立刻,不需要时钟要等时钟沿
      时钟没起来时照样有效 —— 上电初始化靠它无效
      毛刺复位线上一个毛刺就能误复位窄毛刺被时钟采样天然滤掉
      释放时刻若靠近时钟沿,有恢复时间风险无此问题
      资源用触发器专用复位端,不占逻辑复位并进数据路径,可能多一层逻辑
      工程上的标准答案:异步复位、同步释放

      两者的优点都要:复位加的时候异步,立刻生效;复位撤的时候同步,避开恢复时间风险。做法是把外部复位先打两拍再送给全局:

      reg [1:0] rst_sync;
always @(posedge clk or negedge rst_n_ext) begin
    if (!rst_n_ext) rst_sync <= 2'b00;
    else            rst_sync <= {rst_sync[0], 1'b1};
end
wire rst_n = rst_sync[1];   // 全局用这个

      这段几乎每个工程的顶层都有一份。第 06 课讲跨时钟同步时会再回到它。

      阻塞与非阻塞:差别在这一张波形上

      规则本身两句话:

      • 阻塞 = —— 立刻生效。下一行读到的是刚写进去的新值,像普通编程语言。
      • 非阻塞 <= —— 块里所有右边表达式先全部用旧值算完,然后一起更新。这正是一排触发器在同一个时钟沿的真实行为。

      光看规则记不住。下面两个模块的代码除了赋值符完全一样,行为差了三倍。

      shift3_nb.v · 非阻塞 
      always @(posedge clk) begin
    q1 <= din;   // 右边取旧值
    q2 <= q1;    // 旧的 q1
    q3 <= q2;    // 旧的 q2
end

      三个触发器串成一条链,数据一拍走一级。写的顺序无所谓,调换三行结果不变。

      shift3_b.v · 阻塞 
      always @(posedge clk) begin
    q1 = din;    // 立刻生效
    q2 = q1;     // 拿到的是 din
    q3 = q2;     // 也是 din
end

      din 一个沿冲到底,三级塌成一级。而且行为依赖书写顺序 —— 调换三行结果就变。

      为什么阻塞赋值在时序块里是真 bug,而不只是“风格问题”
      • 结果依赖书写顺序。把三行调个顺序,电路就变了 —— 而硬件里那三个触发器本来是并列的,没有顺序。
      • 如果两个 always 块都用阻塞赋值、又互相读对方的信号,谁先执行由仿真器决定。同一份代码在不同仿真器上可能给出不同结果,更糟的是仿真通过、上板不对。
      • 综合工具的解读可能和仿真器不一致,于是出现最难查的一类 bug:仿真是对的,芯片是错的。

      看 {q3,q2,q1} 这一列:非阻塞版本是 001 → 010 → 100,一个 1 在三级之间走;阻塞版本第一拍就是 111,三级同时被填满,下一拍又同时清空。波形和终端日志说的是同一件事,两个都要会看。

      三条不许违反的规矩

      1. 时序 always 一律用 <=,组合 always 一律用 =。不要在同一个 always 块里混用两种赋值符。
      2. 一个信号只在一个 always 块里被赋值。违反就是多驱动。
      3. 组合 always 的每个分支都要给所有输出赋值,做不到就在块开头统一给默认值。否则综合出锁存器(第 05 课会专门看它长什么样)。
      模板背下来,后面八课都在用它 
      // 时序:寄存 + 复位
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) q <= 复位值;
    else if (en) q <= 新值;      // 没有 en 就保持,不用写 else
end

// 组合:先默认值,再分情况
always @(*) begin
    y = 默认值;
    case (sel)
        …: y = …;
        default: y = 默认值;
    endcase
end

      练习

      1. 把阻塞版本的三行倒过来写热身

        把 shift3_b.v 里的三行改成 q3 = q2; q2 = q1; q1 = din;(顺序反过来),重跑 shift_cmp_tb。现在两列一样了吗?这个结果说明了什么?

        参考答案

        一样了。倒着写时,每一行读到的都还是这个沿之前的旧值,于是碰巧等价于非阻塞。

        但这恰恰是不能用阻塞赋值的理由:正确性建立在“行的顺序刚好写对”上。三行还能人肉检查,十几行加上 if、case 嵌套就无从检查了;而且下一个改代码的人不知道这个顺序是有意义的,随手一调就出 bug。非阻塞赋值把顺序这件事从等式里彻底消掉。

      2. 8 位串入并出移位寄存器动手

        写 code/lesson03/shift8.v:每个时钟沿把 din 从低位移进来,输出 8 位 q。核心只有一行。写 TB 依次送入 1 0 1 1 0 0 1 0,验证 8 拍后 q 等于 8'b1011_0010。

        参考答案
        module shift8 (
    input  wire       clk,
    input  wire       rst_n,
    input  wire       din,
    output reg  [7:0] q
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) q <= 8'd0;
        else        q <= {q[6:0], din};   // 整体左移一位,din 补到最低位
    end
endmodule

        要凑出 8'b1011_0010,得先送最高位:依次送 1,0,1,1,0,0,1,0。因为最先进来的那一位会被后面 7 次移位一路推到最高位 —— 这就是串行协议里“MSB first”的含义。UART 恰恰相反,是 LSB first,第 10 课会用到。

        顺手体会一下:8 位移位寄存器和 8 位并行寄存器占用的触发器数量完全一样,区别只在前面接的组合逻辑不同。

      3. 两级流水加法器动手

        写 pipe_add.v:第一级把 a、b 寄存下来,第二级寄存它们的和,输出 9 位 sum。写 TB 观察:给一组输入后,正确结果在第几拍出现?

        参考答案
        module pipe_add (
    input  wire       clk,
    input  wire       rst_n,
    input  wire [7:0] a,
    input  wire [7:0] b,
    output reg  [8:0] sum
);
    reg [7:0] a_r, b_r;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            a_r <= 8'd0;
            b_r <= 8'd0;
            sum <= 9'd0;
        end else begin
            a_r <= a;                // 第一级:寄存输入
            b_r <= b;
            sum <= a_r + b_r;        // 第二级:用的是上一拍的 a_r、b_r
        end
    end
endmodule

        结果在第 2 拍出现。关键就在 sum <= a_r + b_r; 用的是旧的 a_r、b_r —— 写在同一个 always 里也照样是两级,这正是非阻塞赋值带来的便利。

        为什么要这么做:把长组合路径切成几段,每段之间插一排触发器,主频就能提上去。代价是延迟变成 2 拍。吞吐率换延迟,是 FPGA 设计里最常用的一招。

      4. Testbench 里的激励为什么也用 <=想清楚

        shift_cmp_tb.v 里写的是 din <= 1'b1; 而不是 din = 1'b1;。把它改成阻塞赋值,重跑几次。为什么在 @(posedge clk) 之后驱动 DUT 输入时,非阻塞更安全?

        参考答案

        因为会出现竞争。@(posedge clk) 醒来之后,TB 和 DUT 的 always 块都排在同一时刻等着执行,谁先跑由仿真器决定:

        • DUT 先跑 → 采到 din 的旧值(这是真实硬件的行为)。
        • TB 先跑,用阻塞赋值立刻改了 din → DUT 采到新值,凭空少了一拍延迟。

        用 din <= 1'b1; 后,这次更新被推到非阻塞更新阶段,一定发生在所有 always 块读完信号之后。DUT 必然采到旧值,行为确定。

        所以规矩再补一条:TB 里凡是对齐时钟沿驱动 DUT 输入的赋值,也用 <=。只有产生时钟本身(always #10 clk = ~clk;)和纯延时序列里才用 =。
