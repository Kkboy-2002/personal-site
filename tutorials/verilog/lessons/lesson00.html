    本课路线

      写 Verilog 到底在写什么

      FPGA 芯片内部是一大片可以配置的资源:查找表(LUT)、触发器(DFF)、块 RAM、DSP 乘法器,以及连接它们的可编程布线开关。综合工具做的事,就是把你写的 Verilog 翻译成“哪些 LUT 装什么真值表、哪些触发器接到哪根线上”。

      所以有一句话要先立住:Verilog 不是编程语言,是电路描述语言。代码里没有“先执行这句再执行那句”,只有“这些硬件同时存在”。

      完整的开发流程有六步,但这门课的前十节只用到前两步:

      1. 写 RTL —— 用 Verilog 描述电路。
      2. 功能仿真 —— 在电脑上验证逻辑对不对。本课就到这里。
      3. 综合 —— 映射到 LUT、DFF、块 RAM。
      4. 布局布线 —— 决定用芯片上哪几个具体资源、怎么连。
      5. 时序分析 —— 确认在目标频率下建立/保持时间都满足。
      6. 生成 bitstream 并下载 —— 上板。
      没有开发板照样能学

      第 3 到第 6 步需要 Vivado / Quartus 和一块板子,但它们不解决“逻辑写错了”的问题。真正的功能 bug 全部在第 2 步暴露。所以先把仿真练熟,买板子的钱可以晚点花。

      第一个模块:每个时钟翻一次

      这个模块只做一件事:每来一个时钟上升沿,输出翻转一次。它的输出频率正好是时钟的一半,所以也叫二分频。

      逐行看:

      • `timescale 1ns/1ps —— 后面写 #10 就表示 10ns,仿真精度 1ps。仅仿真
      • module toggle ( … ); 到 endmodule —— 一个模块的全部边界。括号里是端口清单。
      • input wire / output reg —— 输入永远是 wire;输出在 always 里被赋值,所以声明成 reg。
      • always @(posedge clk or negedge rst_n) —— 敏感列表。这一句就决定了它会被综合成一个带异步复位的触发器。
      • q <= ~q; —— 非阻塞赋值。读到的 q 是这个沿之前的值,写进去的是沿之后的新值。这正是触发器的行为。
      output reg 不代表“寄存器”

      reg 只是“能在过程块里被赋值的变量”。这里之所以真的综合出触发器,是因为它写在 @(posedge clk) 的 always 里。同一个 reg 写在 always @(*) 里就只是一堆组合逻辑。这一点第 03 课会专门拆开讲。

      Testbench:仿真世界里的“外部电路”

      设计文件里没有时钟源,也没有人按复位键 —— 这些都由 Testbench 提供。一个 Testbench 永远只干三件事:产生时钟、驱动激励、记录波形。

      Testbench 里的每一种写法
      写法含义
      module toggle_tb;Testbench 自己是顶层,不需要端口
      reg clk = 1'b0;激励信号由 TB 驱动,所以是 reg,声明时可直接给初值
      wire q;DUT 的输出只能观察,用 wire 接
      always #10 clk = ~clk;无终止条件的时钟源;这里用阻塞赋值 = 是标准写法
      .clk (clk)按名字连接:左边是 DUT 的端口名,右边是 TB 的信号名
      $dumpfile / $dumpvars缺任何一句都不会生成 .vcd,也就没有波形可看
      $timeformat(-9, 0, "", 10)让 %t 按 ns 打印。不写这句,timescale 的精度是 1ps,%t 会把 71ns 印成 71000
      @(posedge clk)“等到下一个上升沿”,是等待而不是判断
      #1沿后延迟 1ns 再采样,避免读到沿上正在变化的值
      $finish忘了写,仿真就永远跑不完(时钟是个死循环)

      波形窗口里最该练的两个动作

      一是量周期:在波形区左键点一下放主游标,右键拖出第二个游标,窗口底部会直接显示时间差。二是找第一次出错的沿:调试时永远从“第一个不对的时刻”往前看,而不是盯着最后的结果猜。

      练习

      四道题都在 code/lesson00/ 里改或新建文件,改完用 .\sim.bat lesson00 <顶层名> 验证。

      1. 把时钟周期改成 8ns热身

        把 TB 里的 always #10 clk = ~clk; 改成 #4,重跑。q 的周期变成多少?为什么整个仿真的总时长也跟着变短了?

        参考答案

        时钟周期变成 8ns,q 的周期是它的两倍 = 16ns。

        总时长变短,是因为这个 TB 的结束条件是“数满 8 个上升沿”,而不是“跑到 200ns”。沿来得快,8 个沿就早早数完,$finish 也就提前执行。这说明一件事:仿真的时间跨度由激励决定。想固定跑 200ns,应该另开一个 initial 写 #200 $finish;。

      2. 把异步复位改成同步复位改一行

        把敏感列表里的 or negedge rst_n 删掉,重跑。波形有变化吗?再把 TB 的复位释放时刻从 #35 改成 #25 试试。什么情况下两种复位才会表现出差别?

        参考答案

        同步复位的写法:

        always @(posedge clk) begin      // 敏感列表里只有时钟
    if (!rst_n) q <= 1'b0;       // 复位也要等时钟沿才生效
    else        q <= ~q;
end

        本例波形几乎看不出差别,因为复位从 0 时刻就按住、中途只释放一次,释放后第一个时钟沿的行为两者相同。

        差别出现在复位脉冲比一个时钟周期还窄的时候:异步复位在拉低的瞬间就把 q 清零,同步复位则可能整个漏掉这个脉冲。代价是异步复位的释放时刻若靠近时钟沿,会有恢复时间(recovery time)风险 —— 工程上常用的折中是“异步复位、同步释放”,第 06 课会写到。

      3. 自己写一个四分频动手

        新建 code/lesson00/div4.v,让 q 每 2 个时钟周期翻转一次(即 q 的周期 = 4 × clk 周期),再写 div4_tb.v 验证。提示:需要一个 1 位的计数器。

        参考答案
        module div4 (
    input  wire clk,
    input  wire rst_n,
    output reg  q
);
    reg cnt;                     // 1 位计数器:0 → 1 → 0 → 1 …

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            cnt <= 1'b0;
            q   <= 1'b0;
        end else begin
            cnt <= ~cnt;         // 每个沿都翻
            if (cnt)             // 只在 cnt 已经是 1 的那个沿让 q 翻
                q <= ~q;
        end
    end
endmodule

        关键在 if (cnt) 读到的是这个沿之前的 cnt。两个沿里只有一个满足条件,所以 q 每两个沿翻一次,周期正好四倍。Testbench 直接把第 00 课的抄过来改个模块名即可。

      4. 把 <= 换成 = 会怎样想清楚

        把 toggle.v 里的 q <= ~q; 改成 q = ~q;,重跑仿真。波形变了吗?为什么这里看不出差别,而“时序逻辑必须用 <=”这条规矩仍然要守?

        参考答案

        波形不变。因为这个 always 块里只有一个赋值,而且没有第二个信号在同一个沿上读 q,阻塞与非阻塞的执行差异体现不出来。

        差别在“同一个时钟沿有多个寄存器互相引用”时才出现,最典型的就是移位寄存器:用 <= 得到一条 3 级移位链,用 = 则可能塌成 1 级 —— 同一份代码在不同仿真器/综合器上还可能给出不同结果。第 03 课会把这两种波形并排画出来。

        所以规矩先无条件记住:时序 always 一律 <=,组合 always 一律 =。
