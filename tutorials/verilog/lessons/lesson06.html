    Lesson 06 ／ 输入处理

    边沿检测与按键消抖

    来自芯片外面的信号 —— 按键、传感器、别的芯片 —— 和你的时钟毫无关系,随时可能在时钟沿上变化。这一课把三个必备套路练熟:打两拍同步、取沿变脉冲、计时消抖。它们短得像模板,但少一个就是上板不稳定的根源。

    学完这一课你能
    说清亚稳态是什么,以及为什么两级触发器能压住它
    用三个触发器 + 一个与门把电平变成单周期脉冲
    写出带计时确认的按键消抖,并用注入抖动的 Testbench 证明它有效
    解释为什么消抖时间要选 10–20ms 这个量级

    本课路线

      先打两拍,再干别的

      触发器要求输入在时钟沿前后各稳定一小段时间(建立时间和保持时间)。异步信号不遵守这个约定,如果它正好在沿上跳变,触发器的输出会进入一个既不是 0 也不是 1 的中间状态,并持续一段不确定的时间才随机落到某一边 —— 这就是亚稳态。

      亚稳态没法消除,只能降低它传播出去的概率。办法是再打一拍:给第一级触发器整整一个时钟周期的时间去稳定下来,第二级几乎总能采到一个干净的 0 或 1。

      两级够不够

      够不够取决于失效间隔(MTBF),它随同步级数呈指数改善。50MHz、信号跳变率不高的场合,两级的 MTBF 已经是几百年量级 —— 完全够。高频(几百 MHz)或跳变很频繁时才考虑三级。

      但两条规矩不能破:一是被同步的信号必须是单比特。多比特总线各位的同步结果可能来自不同拍,拼出一个从未存在过的数值 —— 多比特要用握手或异步 FIFO(第 09 课)。二是同步链上不许插组合逻辑,d0 到 d1 之间必须是直连。

      复位本身也是异步的:异步复位、同步释放

      第 00 课和第 03 课都欠了这笔账,现在还上 —— 因为它用的正是刚才那个打两拍的电路。

      问题在这里:复位信号来自按键或电源监控芯片,它什么时候撤销和你的时钟毫无关系。如果撤销时刻正好落在时钟沿附近,芯片里成千上万个触发器不会同时退出复位 —— 有的赶上了这一拍,有的要等下一拍。状态机于是可能落进一个非法状态组合,而这种失败是概率性的、每次上电表现都不同。

      手册里管这叫恢复时间(recovery time)违例。解法是把两者的优点都要:

      • 加复位时异步 —— 不管有没有时钟,拉低就立刻生效。上电时钟还没起来也管用。
      • 撤复位时同步 —— 让释放动作对齐到时钟沿,全芯片同一拍退出复位。

      看那句 {rst_sync[0], 1'b1} —— 复位释放后,一个 1 从低位往高位挤,两拍之后 rst_sync[1] 才变高。这就是第 03 课练习二那个移位寄存器,换了个用途。

      三条容易漏的细节
      • 这个模块自己用的是异步复位(敏感列表里有 negedge rst_n_ext),它是全芯片唯一一个直接吃外部复位的地方。其余所有模块都用同步化之后的 rst_n。
      • 每个时钟域各要一份。设计里有两个时钟,就要两条这样的链,各自用自己的时钟。共用一份等于又制造了一次跨时钟域。
      • Vivado 里给 rst_sync 加 (* async_reg = "true" *),和同步器一个道理。

      边沿检测:把电平变成脉冲

      为什么一定要变成单周期脉冲

      因为下游几乎总是写 if (rise) cnt <= cnt + 1; 这种代码。如果直接用电平去使能,按键按住 0.2 秒就是一千万个时钟周期,计数器会一路加到爆。“一次事件对应一个脉冲”是整个同步设计的基本约定,状态机的启动信号、FIFO 的读写使能、串口的发送请求,全都依赖它。

      按键抖动:金属片真的会弹

      机械按键的两片金属接触时会物理弹跳几次,电气上表现为几毫秒内高低乱跳十几次。在 50MHz 时钟看来,这是几十万个时钟周期的混乱 —— 你写的边沿检测会老老实实报告十几个上升沿。

      整个模块的关键就是那个 else cnt <= 0; 分支 —— 只要输入抖回去一次,计时就从头开始。这比“检测到边沿后延时若干毫秒再采样一次”的写法更稳:后者如果延时结束时恰好落在另一次抖动上,照样会判错。

      STABLE 该选多大
      取值(50MHz)对应时间后果
      50_0001 ms比抖动时间还短,抖动会漏过去
      1_000_00020 ms常用值,机械按键抖动一般 5–10ms
      5_000_000100 ms手感发黏,快速连按会丢键

      验证消抖的正确姿势

      不要只测“按一下能不能识别”,那太容易通过了。要测的是抖动能不能被挡住 —— 所以 key_debounce_tb.v 里的 press 任务故意用 17ns、9ns、13ns、7ns 这种非整数倍时钟周期的奇怪延时来造抖动。整数倍的抖动是最容易通过的一种,专挑它测等于没测。

      把 press 里最后那段稳定时间从 #400 改成 #60(不够 STABLE),再跑一次:key_down 应该一次都不出现。测“该不响应的时候不响应”和测“该响应的时候响应”同样重要。

      练习

      1. 能不能少用一个触发器热身

        把 edge_det.v 里的 d2 删掉,改成 assign rise = d1 & ~d0;,重跑 edge_det_tb。脉冲数还对吗?这样写有什么隐患?

        参考答案

        脉冲数仍然是 2 和 2,只是每个脉冲提前了一拍出现 —— 功能上“对”。

        隐患在于 d0 可能正处于亚稳态。把一个还没落定的信号送进组合逻辑,那个中间电平会在与门、非门里被放大成毛刺,再扩散给所有用到 rise 的下游 —— 一次亚稳态污染一片电路。

        所以同步链有一条硬规矩:第一级的输出只能接第二级,不许参与任何其他逻辑。省下的那一个触发器,是 FPGA 里最不值得省的资源。

      2. 按键计数器动手

        写 code/lesson06/key_cnt.v:例化 key_debounce,每按一次键让 8 位 led 加一。写 TB 连按三次,验证 led 恰好是 3。

        参考答案
        module key_cnt #(
    parameter STABLE = 1_000_000
)(
    input  wire       clk,
    input  wire       rst_n,
    input  wire       key_in,
    output reg  [7:0] led
);
    wire key_down;

    key_debounce #(.STABLE(STABLE)) u_key (
        .clk       (clk),
        .rst_n     (rst_n),
        .key_in    (key_in),
        .key_state (),                 // 用不到,悬空
        .key_down  (key_down),
        .key_up    ()
    );

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)        led <= 8'd0;
        else if (key_down) led <= led + 1'b1;   // 一个脉冲加一次
    end
endmodule

        这就是把电平变成脉冲的回报:计数逻辑只有一行,而且不管按住多久都只加一。如果这里换成 if (key_state),按住半秒就能加两千五百万次。

      3. 长按检测动手

        写 key_long.v:在 key_debounce 之外再加一层,按住超过 LONG 个时钟就输出一个 long_press 单周期脉冲,而且按住不放也只输出一次。

        参考答案
        module key_long #(
    parameter STABLE = 1_000_000,
    parameter LONG   = 50_000_000     // 50MHz → 1 秒
)(
    input  wire clk,
    input  wire rst_n,
    input  wire key_in,
    output reg  long_press
);
    wire key_state, key_up;

    key_debounce #(.STABLE(STABLE)) u_key (
        .clk(clk), .rst_n(rst_n), .key_in(key_in),
        .key_state(key_state), .key_down(), .key_up(key_up)
    );

    reg [$clog2(LONG)-1:0] hold;
    reg                    fired;      // 这次按住已经报过了

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            hold       <= 0;
            fired      <= 1'b0;
            long_press <= 1'b0;
        end else begin
            long_press <= 1'b0;        // 默认只高一拍

            if (!key_state) begin      // 松开了 → 全部复位,等下一次
                hold  <= 0;
                fired <= 1'b0;
            end else if (!fired) begin
                if (hold == LONG - 1) begin
                    long_press <= 1'b1;
                    fired      <= 1'b1;   // 打上标记,按住也不再报
                end else begin
                    hold <= hold + 1'b1;
                end
            end
        end
    end
endmodule

        两个技巧值得记住:long_press <= 1'b0; 写在块开头当默认值,后面某个分支再拉高 —— 这样自动就是单周期脉冲,不用另写清零逻辑;fired 标志保证“一次按住只报一次”,松开时清掉。这两招在状态机里天天用。

      4. 为什么多比特不能各自打两拍想清楚

        一个 8 位计数器在另一个时钟域里跑,你想把它同步过来看。如果给 8 位各接一条两级同步器,会出什么问题?举一个具体的数值例子。

        参考答案

        计数器从 8'h7F 加到 8'h80 时,8 位同时翻转。八条同步链是各自独立的,某几位可能采到了新值、另几位还是旧值 —— 你读到的可能是 8'hFF、8'h00、8'hBF…… 全都是从未真实存在过的数值。而且它不是每次都错,概率性出现,极难复现。

        三种正确做法:

        • 格雷码。让相邻两个值只差一位,这样最坏情况也只是采到旧值或新值,不会采到第三个值。异步 FIFO 的读写指针就用它。
        • 握手。数据放在普通寄存器里保持稳定不动,只把一位 valid 同步过去;对方看到 valid 才去取数据。单比特同步是安全的,数据靠“稳定不动”来保证。
        • 异步 FIFO。上面两招的成品封装,吞吐量大时用它。

        记住这条边界:两级同步器只对单比特有效。它是这一课唯一一个用错了会随机出错、而仿真通常抓不到的地方。
