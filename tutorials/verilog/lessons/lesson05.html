    Lesson 05 ／ 分支与显示

    if 与 case:译码与显示

    分支语句本身没什么难的,难的是知道自己写出了什么电路。if 串成优先级链,case 摊成并行选择;而一个漏掉的 else 会悄悄给你造一个锁存器。这一课把这三件事看清楚,然后做出能显示四位数字的数码管。

    学完这一课你能
    根据条件是否互斥,在 if…else if 和 case 之间做出正确选择
    在波形上认出一个被无意生成的锁存器,并说清它为什么是 bug
    写出七段数码管译码器,并遍历 16 个数字自检
    实现四位数码管动态扫描,解释为什么四位共用一套段线还能各显其字

    本课路线

      if 和 case 综合出来不一样

      第 02 课已经埋过伏笔:if…else if 是优先级链,case 是并行选择。判据只有一条 —— 条件之间会不会同时成立。

      条件互斥 → 用 case 
      case (sel)
    2'd0: y = a;
    2'd1: y = b;
    2'd2: y = c;
    default: y = d;
endcase

      sel 只可能是一个值,四个分支天然互斥。综合成一层选择器,路径最短。

      条件会同时成立 → 用 if 链 
      if      (err)   y = 2'd3;
else if (full)  y = 2'd2;
else if (valid) y = 2'd1;
else            y = 2'd0;

      err、full、valid 可以同时为 1,必须规定谁赢。这里的优先级就是需求本身。

      把互斥的条件写成 if 链的代价

      只是白白拉长关键路径。八个分支的 if 链就是八级选择器串联;同样的逻辑写成 case 是一级。功能一模一样,主频可能差一倍。综合工具有时能识别出互斥并自行优化,但不要指望它。

      锁存器:一个漏掉的 else

      组合 always 块的铁律是:每条执行路径都必须给所有输出赋值。做不到,综合工具就得想办法让输出“记住”上次的值 —— 于是它生成一个锁存器。

      为什么锁存器在 FPGA 里是 bug 而不是特性
      • 电平敏感,不是边沿敏感。使能打开期间输入的任何毛刺都会穿透过去,不像触发器只在沿上采一次。
      • 时序分析没法做。工具无法给锁存器算出可靠的建立/保持关系,时序报告直接失去意义。
      • FPGA 里没有原生锁存器。工具得用查找表加反馈环路凑出来,面积大、延迟不可控。
      • 它是无声的。综合日志里只有一条 inferred latch for 'y_bad' 警告,混在几百条 warning 里,没人看见。

      预防办法只有两个,任选其一:组合块开头统一赋默认值,或者保证 if 有 else、case 有 default。

      七段译码器:case 的标准场合

      七段数码管有七个段 a–g,点亮不同组合就显示不同字符。段位顺序约定成 seg = {g,f,e,d,c,b,a},共阴管高电平点亮。

      16 个分支已经全覆盖了,为什么还要 default

      因为 num 在仿真里可能是 x。没有 default 时,num = 4'bxxxx 会让所有分支都不匹配,seg 保持旧值 —— 又是一个锁存器。加上 default 后 x 会被明确地映射成“全灭”,而且综合结果不受影响。无条件写 default,不要去论证它用不上。

      动态扫描:四位共用一套段线

      一个四位数码管只有 7 根段线 + 4 根位选线,不可能同时显示四个不同数字。做法是飞快地轮流点亮:每次只让一位接通,给它送对应的段码,一位停留约 1ms,四位轮完一圈 4ms(250Hz),人眼看起来就是四位同时亮着。

      三个值得注意的地方:idx 是 2 位的,自然回绕不需要判满;case 的每个分支里 digit 和 sel 都被赋值(少赋一个就出锁存器);digit 是 reg,但它可以直接接到子模块的 input 端口上。

      波形里最该确认的是 sel 和 seg 必须同时切换。如果 seg 比 sel 晚一拍(比如你不小心把 digit 寄存了一下),那么在切换的那一拍里,新的一位会短暂地显示上一位的字符 —— 上板表现为“数码管发虚、串影”。这个现象在波形上是一拍的错位,在板子上是肉眼可见的模糊。

      casez、casex 与两个别用的指令

      case 的三个变种
      写法行为建议
      case逐位精确比较,x/z 只和 x/z 匹配首选
      casez分支里的 ? 和 z 当无关位可用写位掩码时很方便
      casexx 也当无关位别用会掩盖真正的 x bug

      casez 的典型用途是把优先编码器写得更好读:

      不要用 full_case 和 parallel_case

      这两个综合指令(写成 // synthesis full_case parallel_case)是在向工具承诺“分支已全覆盖”“分支互斥”。承诺错了,综合结果和仿真结果就会不一致 —— 这是最难查的一类 bug,因为仿真永远是对的。

      需要表达同样的意思时,用 SystemVerilog 的 unique case / priority case:它们在仿真时也会检查你的承诺,违反了直接报错。要么就老老实实把 default 写全 —— 代价通常是零。

      练习

      1. 删掉 default,让 x 现形热身

        把 seg7_dec.v 的 default 那一行删掉。在 seg7_tb.v 最后加两行:num = 4'bxxxx; #5 $display("seg=%b", seg);。seg 是什么?加回 default 再看一次。

        参考答案

        删掉 default 时,num = 4'bxxxx 让 16 个分支全都不匹配,seg 于是保持上一次的值(4'hF 对应的 1110001)。这就是本课开头那个锁存器,只不过这次它藏在 case 里。

        加回 default 后 seg = 0000000,x 被明确处理掉了。

        更狠一点的做法是让 default 在仿真里主动报警:

        default: begin
    seg = 7'h00;
    // synthesis translate_off
    $display("[警告] %0t ns: seg7_dec 收到非法输入 num=%b", $time, num);
    // synthesis translate_on
end

        translate_off/on 之间的代码综合时被忽略,仿真时照跑。这是给 default 加“报警器”的标准手法。

      2. 给译码器加消隐和小数点动手

        给 seg7_dec 加两个端口:输入 blank(为 1 时整位全灭)、输入 dp_en 和输出 dp(小数点)。要求改完之后仍然一个锁存器都不产生。

        参考答案
        module seg7_dec (
    input  wire [3:0] num,
    input  wire       blank,     // 1 = 这一位不显示
    input  wire       dp_en,     // 1 = 点亮小数点
    output reg  [6:0] seg,
    output wire       dp
);
    assign dp = dp_en & ~blank;  // 消隐时小数点也灭

    always @(*) begin
        if (blank) begin
            seg = 7'h00;         // 消隐优先,直接返回
        end else begin
            case (num)
                4'h0: seg = 7'h3F;
                // … 其余 15 个分支不变 …
                default: seg = 7'h00;
            endcase
        end
    end
endmodule

        关键点:if (blank) 的两个分支都给 seg 赋了值,case 里也有 default —— 每条路径都有赋值,所以还是纯组合。消隐功能在实际项目里很常用:显示 0012 时把前两位消掉,变成 12。

      3. 4-16 译码器,两种写法动手

        写 dec4to16.v:输入 4 位 num,输出 16 位 one-hot(只有第 num 位为 1)。先用 case 写 16 个分支,再用一行表达式重写。两者综合结果一样吗?

        参考答案
        // 写法一:case,16 个分支
always @(*) begin
    case (num)
        4'd0:    y = 16'h0001;
        4'd1:    y = 16'h0002;
        // … 一直到 4'd15 …
        default: y = 16'h0000;
    endcase
end

// 写法二:一行
assign y = 16'h0001 << num;

        综合结果基本一样 —— 两者都是标准的 4-16 译码器,工具会把它映射成同一堆 LUT。但第二种少写 16 行、不可能打错某一位,而且加参数化就能变成任意宽度的译码器。

        能用一个表达式说清的结构,就不要摊成 case 表。case 表留给真的没有规律的映射,比如上面的七段译码。

      4. 扫描频率怎么选想清楚

        默认 DIV = 50_000,时钟 50MHz。算一算每位点亮多久、整屏刷新率多少。如果把 DIV 改成 500_000 或 500,分别会看到什么?

        参考答案

        每位点亮时间 = 50000 / 50MHz = 1ms;四位轮一圈 4ms,整屏刷新率 = 250Hz。公式就是 DIV = f_clk × t_digit。

        • DIV = 500_000 → 每位 10ms,刷新率 25Hz。低于人眼临界闪烁频率(约 50–60Hz),会看到明显的一位一位跳,像走马灯。
        • DIV = 500 → 每位 10µs,刷新率 25kHz。理论上更平滑,实际上更糟:段线上有寄生电容、位选三极管有开关延迟,几微秒的点亮时间里电压还没建立完就切走了,结果是整屏发暗、相邻位串影。

        工程上的常用区间:整屏刷新 60–1000Hz,每位点亮 0.5–5ms。默认值 1ms/250Hz 落在中间,既不闪也不虚。
