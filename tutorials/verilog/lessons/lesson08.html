    Lesson 08 ／ 复用与生成

    参数化与 generate

    同一个功能写第二遍,就说明第一遍写得不够通用。这一课把模块变成“可配置的零件”:位宽、级数、有没有某一块电路,全都由参数决定。generate 让你用四行代码生成八份相同的硬件,或者干脆让某块电路根本不存在。

    学完这一课你能
    分清 parameter、localparam 和 `define 各自的场合
    用 generate for 批量例化,并读懂 gen_x[3].u_y 这种层次路径
    用 generate if 让一块电路按参数存在或消失
    写出位宽任意的格雷码转换,并解释它为什么能用于跨时钟域

    本课路线

      三种“常量”,别搞混

      parameter / localparam / `define
      作用域能否被外部覆盖用来做什么
      parameter本模块能,例化时用 #(.W(16))位宽、深度、分频比 —— 一切调用者该决定的量
      localparam本模块不能状态编码、内部推导出来的常量
      `define全局,从定义处到文件末尾(甚至跨文件)用 `undef 取消条件编译开关,别拿它当常量用
      `define 是文本替换,不认作用域

      `define W 8 之后,后面编译的所有文件里的 `W 都被替换成 8。两个模块想用不同位宽就彻底冲突,而且报错信息指向替换后的行,极难定位。常量一律用 parameter / localparam,`define 只留给 `ifdef SIM 这类条件编译。

      $clog2 和参数化的日常

      参数化最常见的连锁反应是位宽:深度一改,地址线宽度就得跟着改。$clog2 把这件事自动化。

      $clog2 的取值,别记错
      N$clog2(N)能表示的范围够不够计到 N
      420 – 3不够(要 $clog2(N+1))
      530 – 7够
      25680 – 255不够
      25790 – 511够

      规律:$clog2(N) 位刚好够表示 0 到 N−1。当 N 是 2 的幂时最容易踩坑,因为差一位就是整个计数器失效(第 04 课练习一验证过这件事)。

      generate for:编译期展开

      generate 里的 for 和软件的循环完全不是一回事。它在编译期就被展开成 N 份并列的硬件,循环变量 genvar 只是个编译期的记号,芯片里根本没有它。

      generate 的 begin 必须命名

      begin : gen_bit 里的名字构成了层次路径。不起名字,有些工具直接报错,能过的工具也会给你生成 genblk1 这类自动名字 —— 于是波形里的路径变成 u_top/genblk1[2]/u/q,而且加一个 generate 块编号就全变了。起名字的成本是零,不起名字的成本是每次调试都要重新猜。

      generate if:让电路消失

      generate if 的条件必须是编译期常量(参数)。它决定的不是“运行时走哪条路”,而是“要不要生成这块硬件”。

      这里有两种循环,别混:

      • generate 外面那个 if —— 编译期判断,决定生成哪一块。
      • always 里面的 for(用 integer k)—— 也是编译期展开,展开成 stage[1]<=stage[0]; stage[2]<=stage[1]; 这样的并列语句。它不是 genvar 循环,因为它没有例化东西,只是在生成赋值语句。
      为什么 STAGES=0 要单独处理

      因为 reg [W-1:0] stage [0:-1]; 是非法的数组声明,编译直接报错。generate if 让这段代码在 STAGES==0 时压根不参与编译 —— 这是它和运行时 if 最本质的区别。参数化模块要支持“退化情况”(0 级流水、深度 1 的 FIFO、位宽 1 的总线),几乎总要靠它。

      格雷码:一个值得参数化的小零件

      格雷码的性质是相邻两个值只差一位。这让它在两个地方不可替代:跨时钟域传计数值(第 06 课练习四),以及机械编码器(旋转到两格之间时,读数最多错一格而不是乱码)。

      先想有没有一行写法,再想 generate

      bin2gray 本来也可以写成 generate for 逐位算 gray[i] = bin[i] ^ bin[i+1],但 bin ^ (bin >> 1) 一行就完事、而且天生参数化。gray2bin 每一位的异或长度不同,才真的需要 generate。

      判据:如果所有位的表达式形状相同,就用向量运算;只有形状逐位不同才用 generate。

      在波形里确认 generate 生成了几份

      GTKWave 的 SST 面板里展开 u_g2b,能看到 gen_bit[0] 到 gen_bit[3] 四个子层级 —— 这就是 generate for 展开的直接证据。把 W 改成 6 再跑,层级会变成六个。看层级树是确认参数化生效的最快办法,比读综合报告快得多。

      练习

      1. 换个位宽,看层级树热身

        把 gray_tb.v 的 W 依次改成 3 和 6 重跑。3 位时应遍历 8 种、6 位时 64 种。在 GTKWave 里展开 u_g2b,数一数 gen_bit 有几个。

        参考答案

        W=3 时 8 行、3 个 gen_bit;W=6 时 64 行、6 个 gen_bit。DUT 一个字都没改。

        顺手确认一件事:bin2gray 里没有 generate,所以它在层级树里没有子层级 —— 一行向量运算就是一层。参数化不一定要靠 generate,这是本课的主要提醒。

      2. 参数化位反转动手

        写 code/lesson08/bit_reverse.v:任意位宽 W,把输入的比特顺序整个颠倒。写 TB 验 W=8 时 8'b1100_1010 反转成什么。这块电路占多少个 LUT?

        参考答案
        module bit_reverse #(
    parameter W = 8
)(
    input  wire [W-1:0] din,
    output wire [W-1:0] dout
);
    genvar i;
    generate
        for (i = 0; i < W; i = i + 1) begin : gen_rev
            assign dout[i] = din[W-1-i];
        end
    endgenerate
endmodule

        8'b1100_1010 反转成 8'b0101_0011。

        占 0 个 LUT —— 它只是把线换个接法,没有任何逻辑运算。这类“零成本”操作还包括固定位数的移位、拼接、取子段。知道哪些操作免费,是估算资源的第一步。

        用途:很多串行协议规定 LSB 先发(UART),而你的数据在寄存器里是 MSB 在左,反转一下就对齐了。第 10 课会遇到这个问题。

      3. 功能可裁剪的计数器动手

        写 counter_cfg.v:两个功能开关参数 —— UPDOWN(是否支持减计数)和 LOADABLE(是否支持置数)。用 generate if 让关掉的功能完全不生成硬件。

        参考答案
        module counter_cfg #(
    parameter W        = 8,
    parameter UPDOWN   = 1,      // 1 = 生成减计数
    parameter LOADABLE = 0       // 1 = 生成置数
)(
    input  wire         clk,
    input  wire         rst_n,
    input  wire         en,
    input  wire         dir,       // 1=加 0=减(UPDOWN=0 时无效)
    input  wire         load,
    input  wire [W-1:0] load_val,
    output reg  [W-1:0] cnt
);
    wire [W-1:0] step_val;

    generate
        if (UPDOWN) begin : gen_updown
            assign step_val = dir ? cnt + 1'b1 : cnt - 1'b1;
        end else begin : gen_uponly
            assign step_val = cnt + 1'b1;      // 减法器根本不存在
        end
    endgenerate

    generate
        if (LOADABLE) begin : gen_load
            always @(posedge clk or negedge rst_n) begin
                if (!rst_n)    cnt <= {W{1'b0}};
                else if (load) cnt <= load_val;
                else if (en)   cnt <= step_val;
            end
        end else begin : gen_noload
            always @(posedge clk or negedge rst_n) begin
                if (!rst_n)  cnt <= {W{1'b0}};
                else if (en) cnt <= step_val;
            end
        end
    endgenerate
endmodule

        关掉的功能是真的不见了:UPDOWN=0 时没有减法器,LOADABLE=0 时 cnt 前面少一级选择器。load 和 load_val 两个端口还在(端口列表不能被 generate 裁剪),但没人用,综合时会被优化掉,只在综合日志里留一条“unused port”的提示。

        这个模式在 IP 核里到处都是:一个模块带十几个功能开关,用户只为自己用到的功能付资源。

      4. genvar 和 integer 到底差在哪想清楚

        gray2bin 用 genvar i,pipe_reg 的 always 里用 integer k。为什么不能反过来?两种 for 循环有什么共同点?

        参考答案

        genvar 是编译期的记号。它只在 generate 块展开的过程中存在,展开完就消失 —— 芯片里没有它,仿真波形里也看不到它。它的工作是给被生成出来的东西(实例、assign、命名块)编号。所以它只能出现在 generate 里。

        integer 是一个真实存在的 32 位有符号变量,和 reg 一样属于运行时。放在 always 里当循环变量,或者在 Testbench 里计数。它不能用在 generate 的循环里,因为编译器展开时它还没有值。

        共同点很关键:两种 for 都是展开,都不是“反复执行”。always 里的 for (k=1; k<STAGES; k=k+1) stage[k] <= stage[k-1]; 综合出来就是 STAGES-1 条并列的赋值,不是一个会跑循环的电路。这也是为什么它的循环边界必须是常量 —— 边界不定,展开不出来。

        一句话记法:genvar 生成结构,integer 生成语句,两者都在编译期摊平。
