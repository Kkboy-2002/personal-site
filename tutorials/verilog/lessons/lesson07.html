    Lesson 07 ／ 有限状态机

    状态机:三段式写法

    凡是“要分几步做完、每步的动作取决于现在走到哪一步”的电路,都是状态机。协议解析、总线时序、启动流程,全部如此。三段式写法是工业界的默认答案 —— 把它写成肌肉记忆,以后所有时序逻辑都有地方放。

    学完这一课你能
    画出状态转移图,并一对一地翻译成三段式代码
    说清三段各自负责什么,以及为什么第二段第一行要写默认值
    在二进制、独热、格雷三种状态编码之间做出选择
    写出带计时器的状态机(交通灯),并保证输出永远处于安全状态

    本课路线

      先画图,再写代码

      状态机的难点不在语法,在于把需求想清楚。顺序永远是:列出状态 → 画转移图 → 逐条翻译成 case。跳过画图直接写代码,通常会漏掉某个转移条件,而漏掉的那一条恰恰是最难在仿真里撞上的。

      下面这个例子:在一串比特流里找出 1101,允许重叠(1101101 算两次)。状态的含义就是“目前已经攒到了多长的有效前缀”。

      三段式:每段只干一件事

      三段的分工
      段写法负责
      第一段always @(posedge clk) + <=只有一句 state <= next_state; 加复位
      第二段always @(*) + =算 next_state。纯组合,不带任何寄存器
      第三段组合或时序,看需要算输出。Moore 只看 state,Mealy 还看输入

      为什么非要分开?因为分开之后每一段都不可能写错:第一段是模板,第二段是转移图的逐条翻译,第三段是输出表。混在一个 always 里写(所谓一段式),状态更新和输出更新会互相干扰,改需求时极易漏改。

      第二段的第一行是全课最重要的一行 
      always @(*) begin
    next_state = state;      // ← 这一行
    case (state)
        …
    endcase
end

      它保证任何路径下 next_state 都有值,于是这个组合块不会退化成锁存器(第 05 课)。同时它表达了正确的语义:“没写明要跳走的,就留在原地”。有了它,case 里只需要写真正要跳转的分支,代码短一半。

      第三段为什么用 next_state 而不是 state

      如果写 found <= (state == S4);,那么 found 会比 state 晚一拍 —— 状态早已离开 S4,found 才亮起来。用 next_state 判断,寄存之后 found 和 state == S4 落在同一拍,时序干净。

      另一种同样正确的写法是 assign found = (state == S4);(纯组合输出)。它没有延迟,但输出上可能带组合毛刺。接到片外或者作为别的模块的使能时,一律用寄存版。

      Moore 还是 Mealy

      两种输出方式
      MooreMealy
      输出取决于只看当前状态当前状态 和 当前输入
      响应速度慢一拍同一拍就出结果
      状态数通常多一个(本例的 S4)少一个
      输出毛刺不受输入抖动影响输入一抖,输出跟着抖
      建议默认选它确实需要少一拍延迟时才用

      本例的 Mealy 版本可以去掉 S4,直接写 assign found = (state == S3) & din; —— 少一个状态、少一拍延迟。但 found 从此直接挂在 din 上,din 有任何毛刺都会传出去。先写 Moore,时序不够再改 Mealy。

      状态编码:三种选法

      N 个状态的三种编码
      编码位宽特点什么时候用
      二进制$clog2(N)触发器最少,但译码逻辑较深状态多(> 16)、面积紧
      独热(one-hot)N每个状态一位,译码只要看一位,最快FPGA 上的默认选择
      格雷$clog2(N)相邻状态只变一位,跳变时毛刺少状态要送出芯片或跨时钟域

      FPGA 里触发器多到用不完,而 LUT 的级数直接决定主频,所以独热编码通常是赢的。好消息是你不用手写独热 —— 用 localparam 给状态起名字,再让工具去选编码:

      不要为了“看起来专业”手写独热

      手写独热(localparam S0 = 5'b00001, S1 = 5'b00010, …)会让 case 的比较变成 5 位全等比较,反而可能比工具自己做的差;而且加一个状态就要把所有常量重排一遍。用名字写代码,把编码交给属性,这是可读性和性能都最好的组合。

      交通灯:带计时器的状态机

      大多数真实状态机不是靠输入触发跳转,而是靠时间:这一步做够多久就进下一步。做法是给状态机配一个计时器,状态一换就清零。

      • state != next_state 是“本拍即将换状态”的判据,用它清零计时器,新状态一进来就从 0 开始数。
      • limit 用一个组合表达式在两个时长之间选,比给每个状态各配一个计时器省得多。
      • 第三段开头 ns = RED; ew = RED; 既是防锁存器的默认值,也是安全默认值:哪怕状态编码跑到了非法值,输出也是全红而不是两边同时绿。安全相关的设计都该这么写。

      状态机在 GTKWave 里怎么看

      把 u_det.state 拖出来,右键 → Data Format → Decimal,就能直接读出 0…4 的状态序列;再把 din 和 found 放在它上下,一眼就能对着转移图核对每一次跳转。调状态机的标准姿势:三行波形 —— 输入、state、输出。

      用 SystemVerilog 的 typedef enum 定义状态时,好一些的波形工具会直接显示状态名字而不是数字,可读性提升很大;iverilog + GTKWave 组合下还是显示数字。

      练习

      1. 改成检测 1011热身

        先在纸上画出检测 1011 的状态转移图(同样允许重叠),再改 seq_det.v。用码流 1011011 验证:应该命中几次?

        参考答案

        状态含义还是“已收到的前缀”:S0(—)、S1(1)、S2(10)、S3(101)、S4(1011)。转移:

        S0: din ? S1 : S0
S1: din ? S1 : S2      // 连续的 1 停在 S1(末位仍是 1)
S2: din ? S3 : S0
S3: din ? S4 : S2      // 收到 0 时,末两位变成 "10" → 退到 S2 而不是 S0
S4: din ? S1 : S2      // 命中后末位是 1 → S1;末位接 0 → "10" → S2

        1011011 命中 2 次:第 1–4 位 1011,第 4–7 位 1011(重叠)。

        注意 S3 收到 0 退到 S2 而不是 S0 —— 这是和 1101 那题最大的区别,也是最容易写错的一条。判断“退到哪里”的方法:把当前已收到的串加上新来的这一位,再找它最长的、同时也是目标串前缀的后缀。

      2. 自动售货机动手

        写 vending.v:商品 1.5 元,只接受 5 角和 1 元硬币(两个单周期脉冲输入 coin50、coin100)。凑够 1.5 元出货(dispense 脉冲);投到 2 元要找回 5 角(change50 脉冲)。

        参考答案

        状态就是“当前已投入的金额”:M0(0)、M50、M100。1.5 元和 2 元不需要状态 —— 到了就立刻出货并回到 M0。

        localparam M0 = 2'd0, M50 = 2'd1, M100 = 2'd2;
reg [1:0] state, next_state;

always @(posedge clk or negedge rst_n)
    if (!rst_n) state <= M0;
    else        state <= next_state;

always @(*) begin
    next_state = state;
    case (state)
        M0:   if (coin50) next_state = M50;
              else if (coin100) next_state = M100;
        M50:  if (coin50) next_state = M100;
              else if (coin100) next_state = M0;   // 1.5 元,出货
        M100: if (coin50) next_state = M0;         // 1.5 元,出货
              else if (coin100) next_state = M0;   // 2.0 元,出货 + 找零
        default: next_state = M0;
    endcase
end

// 输出:Mealy,因为出货取决于“哪一枚硬币刚进来”
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        dispense <= 1'b0;
        change50 <= 1'b0;
    end else begin
        dispense <= (state == M50  && coin100)
                 || (state == M100 && (coin50 || coin100));
        change50 <= (state == M100 && coin100);
    end
end

        这题的价值在于:状态数应该等于“需要记住的信息量”,而不是流程图上的框数。“已投 1.5 元”不需要状态,因为一到就立刻处理完了。新手常见的错误是给每个金额都建状态,结果状态数翻倍还容易漏转移。

        TB 要覆盖的路径:5+5+5、5+100、100+5、100+100(带找零)、以及“投一半不投了”。

      3. 给交通灯加行人按钮动手

        加一个输入 ped_req(行人请求,单周期脉冲)。要求:主路绿灯期间收到请求,把绿灯剩余时间截短(最多再走 T_MIN 拍就转黄);其他状态下请求先记下来,不影响当前流程。

        参考答案
        reg ped_pending;                     // 记住有人按过

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)                        ped_pending <= 1'b0;
    else if (ped_req)                  ped_pending <= 1'b1;
    else if (state == NS_Y)            ped_pending <= 1'b0;  // 已经响应了,清掉
end

// 绿灯的结束条件多了一条:有人在等,且最短绿灯时间已过
wire ns_done = timeout
            || (ped_pending && state == NS_G && timer >= T_MIN - 1);

always @(*) begin
    next_state = state;
    case (state)
        NS_G:    next_state = ns_done ? NS_Y : NS_G;
        NS_Y:    next_state = timeout ? EW_G : NS_Y;
        EW_G:    next_state = timeout ? EW_Y : EW_G;
        default: next_state = timeout ? NS_G : EW_Y;
    endcase
end

        两个要点。一是 ped_pending 这个“记事本”寄存器:请求是单周期脉冲,状态机不一定当场就能处理,必须先存下来。这是同步设计里极常见的模式 —— 事件用脉冲传递,用寄存器记住。

        二是 T_MIN 最短绿灯时间:不能让行人按一下就立刻切灯,否则正在通过路口的车会被拦在中间。真实控制系统里这类“最小驻留时间”约束到处都是。

      4. 状态跑飞了怎么办想清楚

        seq_det 的 state 是 3 位,能表示 8 个值,但只用了 5 个。剩下 3 个编码万一被进入了,会发生什么?default: next_state = S0; 起了什么作用?独热编码时情况又如何?

        参考答案

        3 位里有 3 个非法编码(5、6、7)。正常逻辑到不了它们,但复位不完全、上电瞬间、或者极端情况下的单粒子翻转都可能让状态落进去。

        default: next_state = S0; 就是自恢复:任何非法状态下一拍就回到 S0,机器最多错一拍。如果没有这一句,第二段第一行的 next_state = state; 会让它永远卡在非法状态 —— 整个模块死掉,而且波形上看起来只是“state 一直是 6”,很难联想到原因。

        独热编码更需要注意:N 位有 2^N − N 个非法编码,比二进制多得多。而且工具做完编码转换后,你写的 default 未必还覆盖得到所有非法组合。两家工具都提供了专门的开关来自动插入恢复逻辑:

        // Vivado
(* fsm_safe_state = "reset_state" *) reg [2:0] state;

// Quartus 在 Settings → Compiler Settings → Advanced 里
// 打开 "Safe State Machine"

        什么时候必须开:会造成物理伤害或数据损坏的设计(电机控制、电源时序、这一课的交通灯)。普通消费电子里,写好 default 通常就够了。
