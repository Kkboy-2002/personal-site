    Lesson 04 ／ 计数与节拍

    计数器、分频与流水灯

    计数器是 FPGA 里出现频率最高的电路 —— 定时、分频、状态机的超时、串口的波特率,底下全是它。这一课把它写成一个能反复例化的模块,顺便纠正一个几乎人人都会犯的错:不要分频出新时钟。

    学完这一课你能
    写出参数化的模 N 计数器,位宽由 $clog2 自动算
    说清“分频时钟”和“时钟使能”的区别,并解释为什么前者是坑
    用一个 tick 驱动流水灯,整个设计只有一个时钟域
    用参数把 0.5 秒的定时压成几百纳秒,让仿真跑得动

    本课路线

      计数器:一个模板走天下

      模 N 计数器只有三个分支,顺序不能乱:先判复位,再判计满,最后才是加一。

      三个细节
      写法为什么
      cnt == MAX - 1计到 MAX-1 就回零,所以一圈恰好 MAX 拍。写成 == MAX 会变成 MAX+1 拍,是最常见的差一错误
      cnt + 1'b1不写成 cnt + 1:裸的 1 是 32 位,会把表达式撑宽。位宽显式化是好习惯
      $clog2(MAX)向上取整的 log₂。MAX=50_000_000 时算出 26,不用自己数位宽
      $clog2 的边界

      $clog2(4) = 2,能表示 0–3,正好够模 4 用。但如果你要计到 包含 MAX 这个值(比如 0…4 共 5 个状态),就得用 $clog2(MAX+1)。差一位就是溢出回零,而且波形上很不容易看出来。

      不要分频出新时钟

      “我要 1Hz 的信号,那就用计数器分频出一个 1Hz 的时钟” —— 这是初学者最常写、也最该改掉的一种代码:

      不要这样写 
      reg clk_1hz;
always @(posedge clk)
    if (tick) clk_1hz <= ~clk_1hz;

// 然后拿它当时钟用
always @(posedge clk_1hz)
    led <= ~led;

      凭空造出第二个时钟域。

      要这样写 
      // 只有一个时钟,tick 当使能
always @(posedge clk)
    if (tick) led <= ~led;

      行为完全一样,但整个设计仍然是单时钟域。

      分频时钟的四宗罪
      • 走普通布线。FPGA 的全局时钟网络是专用资源,数量有限;LUT 产生的时钟走普通线,到各处的延迟不一致,天生带偏斜(skew)。
      • 时序分析报不准。工具默认不认识这个“时钟”,你得手写约束去声明它,漏了就等于没做时序分析。
      • 凭空多一个时钟域。两个域之间传信号就要做跨时钟同步,不做就有亚稳态风险(第 06 课)。
      • 组合逻辑上的毛刺会变成假时钟沿,让下游寄存器莫名跳变。

      真要一个不同频率的时钟(比如给外设供时钟),用芯片里的 PLL / MMCM IP,别用逻辑分频。

      流水灯:tick 当使能怎么用

      • counter #(.MAX(DIV)) —— 例化时传参数,和传端口一样按名字写。
      • .cnt () —— 用不到的输出留空。输入端口不能留空(会变成 z),输出端口可以。
      • else if (tick) 后面没有 else —— 时序块里不赋值就是保持,这正是我们要的行为。组合块里可就不行了。
      • 循环左移用拼接:{led[6:0], led[7]},最高位绕回最低位。

      让仿真跑得动:把参数改小

      DIV = 25_000_000 意味着换一次灯要 25000000 × 20ns = 0.5 秒的仿真时间。仿真器要老老实实算 2500 万个时钟沿,几分钟过去了才看到第一次变化 —— 这不是仿真的用法。

      整门课最实用的一个技巧

      把时间相关的量全部做成 parameter,上板用真实值,仿真时在例化处压到几个时钟。功能逻辑一个字都不用改:

      // 上板
led_flow u_led (…);                  // 用默认 DIV = 25_000_000

// 仿真
led_flow #(.DIV(4)) u_led (…);       // 4 个时钟就换一次灯

      这条习惯会一直用到第 10 课的 UART —— 那里的波特率分频比是 5208,仿真时压到 8 就够验证协议了。

      练习

      1. 制造一次差一错误热身

        先把 counter_tb.v 的 MAX 改成 10 验证一遍。然后把 counter.v 里的 cnt == MAX - 1 改成 cnt == MAX,分别用 MAX=10 和 MAX=8 跑一次。MAX=8 时发生了什么?

        参考答案

        MAX=10 时:$clog2(10)=4,4 位能数到 15,所以 cnt 能走到 10,只是一圈变成 11 拍 —— 一个安静的差一错误。

        MAX=8 时:$clog2(8)=3,3 位最大只能表示 7。cnt 永远等不到 8,回零分支永远不成立,计数器变成靠自然溢出的模 8 计数器,而 tick 恒为 0 —— 下游整个不动,而且编译毫无警告。

        这就是为什么“MAX-1”这一个减一必须写对:位宽刚好够的时候,差一错误会直接让电路失效而不是只偏一拍。

      2. 8 位 PWM动手

        写 code/lesson04/pwm.v:输入 8 位 duty,输出 pwm_out,占空比 = duty/256。核心是一个计数器加一次比较。写 TB 分别验 duty=0、64、255。

        参考答案
        module pwm (
    input  wire       clk,
    input  wire       rst_n,
    input  wire [7:0] duty,          // 0 … 255
    output wire       pwm_out
);
    reg [7:0] cnt;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) cnt <= 8'd0;
        else        cnt <= cnt + 1'b1;   // 8 位自然溢出,正好模 256
    end

    assign pwm_out = (cnt < duty);       // cnt 在低段时输出高
endmodule

        验证要点:duty=0 时输出恒低;duty=255 时占空比是 255/256,到不了 100%。要真正的满占空,把比较器做成 9 位({1'b0,cnt} < {1'b0,duty} + 1)或者对 duty==255 特判。这类“端点差一”在调亮度时会表现为“最亮档还是有一点闪”。

      3. 呼吸灯动手

        写 breath_led.v:让 LED 的亮度自动由暗到亮、再由亮到暗,循环往复。提示:在 PWM 外面套一个慢速的 tick,每个 tick 让 duty 走一步,加一个方向寄存器控制加还是减。

        参考答案
        module breath_led #(
    parameter STEP_DIV = 100_000     // 每 STEP_DIV 个时钟走一步亮度
)(
    input  wire clk,
    input  wire rst_n,
    output wire led
);
    wire       tick;
    reg  [7:0] duty;
    reg        up;                   // 1 = 正在变亮

    counter #(.MAX(STEP_DIV)) u_cnt (
        .clk(clk), .rst_n(rst_n), .cnt(), .tick(tick)
    );

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            duty <= 8'd0;
            up   <= 1'b1;
        end else if (tick) begin
            if (up) begin
                if (duty == 8'd254) up <= 1'b0;   // 到顶了,换方向
                duty <= duty + 1'b1;
            end else begin
                if (duty == 8'd1)   up <= 1'b1;   // 到底了,换方向
                duty <= duty - 1'b1;
            end
        end
    end

    pwm u_pwm (.clk(clk), .rst_n(rst_n), .duty(duty), .pwm_out(led));
endmodule

        换向判断故意用 254 和 1 而不是 255 和 0:因为 up 和 duty 在同一个沿更新,判断用的是旧值。用边界值会多停一拍或者直接绕回去 —— 自己把两种都跑一遍,在波形上看 duty 的顶点长什么样,这个练习的价值全在这里。

        仿真时把 STEP_DIV 压到 2,几微秒就能看到一个完整的呼吸周期。

      4. tick 为什么不寄存一拍想清楚

        counter.v 里 tick 是 assign 出来的组合信号。如果改成寄存一拍(always @(posedge clk) tick_r <= (cnt == MAX-1);),流水灯的行为会有什么变化?什么情况下反而应该寄存?

        参考答案

        组合版本的 tick 和 cnt 同时有效,所以下游在同一个时钟沿动作,而这个沿也正是 cnt 回零的沿 —— 节拍严丝合缝,例化者不需要知道 counter 内部有几级延迟。

        寄存一拍后,下游整体晚一拍动作。单独用一个 tick 时看不出问题(周期还是 MAX),但一旦有的模块用组合 tick、有的用寄存版,两边的节拍就错开一拍,这类 bug 在波形上极难发现。

        什么时候该寄存:MAX 很大时(比如 26 位),cnt == MAX-1 是一个 26 位比较器,再往下游驱动一大片逻辑,这条组合路径可能成为关键路径卡住主频。这时的正确做法是提前一拍比较再寄存:

        always @(posedge clk)
    tick_r <= (cnt == MAX - 2);   // 提前一个数比较,寄存后正好对齐

        既缩短了组合路径,又没有改变节拍。这是时序收敛阶段的常规手段。
