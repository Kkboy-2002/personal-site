I²C 两线总线工作流程

Inter-Integrated Circuit —— 两根线 + 地址寻址,挂满一板子外设

🏠 协议总览 ① 总线拓扑 ② 时序波形 ③ 完整流程 ④ 特点速查

1总线拓扑:SDA + SCL 两根线,靠 7 位地址点名

I²C 只用两根线:SDA 数据线、SCL 时钟线,都是开漏输出 + 上拉电阻: 芯片只能把线「拉低」,松手后靠电阻回到高电平。每个从机出厂带一个 7 位地址, 主机通信前先广播地址,谁匹配谁应答。点击播放主机访问 EEPROM(地址 0x50)的寻址过程。

同一条总线可挂 100 多个器件(受地址数与电容限制),只要地址不冲突。
为什么用开漏?
任何器件拉低都能生效(线与),既避免了推挽输出打架短路,又是仲裁和时钟拉伸的基础。
时钟拉伸
从机来不及处理时,可以按住 SCL 不放(保持低),主机被迫等待 —— 慢设备的「暂停键」。
多主仲裁
两个主机同时发数据,发 1(松手)却读到 0(被别人拉低)的一方退出 —— 与 CAN 同款线与仲裁。

2时序波形:START → 地址+读写位 → ACK → 数据 → ACK → STOP

两条铁律:SCL 高电平期间 SDA 必须保持稳定(此时采样);SCL 高电平期间 SDA 变化只有两个特权时刻—— 下跳 = START,上跳 = STOP。 下面演示:主机向地址 0x50 的器件写一个字节 0xA5 的完整波形。

ACK 槽里主机松开 SDA,由从机拉低表示「收到」;若保持高电平(NACK)说明无人应答。

4特点速查:I²C vs SPI 怎么选?

维度I²CSPI
线数2(SDA+SCL)4 + 每从机一根 CS̅
寻址7/10 位地址,协议内建片选线硬件点名
速率100k / 400k / 1M / 3.4Mbps常见 10~50MHz,更快
双工半双工全双工
应答确认每字节有 ACK/NACK无,靠上层
多主支持支持,线与仲裁基本不支持
典型器件EEPROM、RTC、温湿度、触摸、摄像头配置口Flash、屏幕、高速 ADC、无线模块
经验法则
低速、多器件、省引脚 → I²C;高速、大数据量 → SPI;出板长距离 → RS-485/CAN。
常见坑:忘装上拉
开漏没有上拉电阻,总线永远起不来;典型取值 2.2k~10kΩ,速率越高阻值越小。
常见坑:地址冲突
两片相同器件地址一样怎么办?用地址脚 A0~A2 改址、换 I²C 多路复用器,或分总线。
一句话总结:I²C = 开漏线与 + START/STOP 定界 + 7 位地址寻址 + 逐字节 ACK;两根线换来慢一点的速度。
