CH.01

数据类型与存储

基本类型大小 ★高频

类型典型 32 位 MCU64 位 PC (Windows)说明
char11标准只规定 =1 字节；是否有符号由编译器决定（ARM GCC 默认无符号！）
short22≥2 字节
int44寄存器字长，嵌入式最常用
long44Linux 64 位下为 8（LP64 模型）
float / double4 / 84 / 8部分 Cortex-M0 无 FPU，浮点靠软件模拟
指针48sizeof(指针) 与指向类型无关
工程习惯：嵌入式代码用 <stdint.h> 的 uint8_t / int16_t / uint32_t 等定宽类型，保证跨平台一致。

signed / unsigned 与整型提升 易错

  • 参与运算时 char/short 先提升为 int；有符号与无符号混合运算，有符号会被隐式转成无符号。
  • 经典陷阱：if (-1 < 0U) 结果为 false（-1 转成 4294967295）。
  • 截断：uint8_t x = 300; → x = 44（300 & 0xFF）。
  • 循环倒计数坑：for (unsigned i = n; i >= 0; i--) 死循环（无符号永远 ≥0）。

sizeof 考点 ★高频

char str[] = "hello";   // sizeof(str) == 6（含 '\0'），strlen == 5
char *p = str;           // sizeof(p) == 4/8（指针本身）
void f(char a[100]);    // 函数内 sizeof(a) == 4/8！数组形参退化为指针
  • sizeof 是编译期运算符（VLA 除外），不是函数；操作数不求值：sizeof(i++) 中 i 不变。
CH.02

运算符与位操作

位操作四件套 ★高频·必背

/* 寄存器操作标准宏，1U 防止符号问题。
   宏 = 编译前的文本替换，见 CH.11；寄存器 = MCU 里控制硬件的内存地址，见 CH.12。
   这四行看不懂不影响本章，记住口诀即可 */
#define BIT_SET(reg, n)   ((reg) |=  (1U << (n)))   // 置位第 n 位
#define BIT_CLR(reg, n)   ((reg) &= ~(1U << (n)))   // 清零第 n 位
#define BIT_GET(reg, n)   (((reg) >> (n)) & 1U)     // 读取第 n 位
#define BIT_TOG(reg, n)   ((reg) ^=  (1U << (n)))   // 翻转第 n 位
  • & 按位与（清零/取位）、| 按位或（置位）、^ 异或（翻转/判不同）、~ 取反。
  • 面试手撕：不用临时变量交换 → a ^= b; b ^= a; a ^= b;
  • 判断 2 的幂：(x & (x-1)) == 0 && x != 0；统计 1 的个数：循环 x &= x-1。

移位与优先级 易错

  • 移位量必须在 [0, 位宽) 内，否则未定义行为（未定义行为 = 标准对结果不做任何保证，编译器可以任意处置，换个平台/优化等级结果就变——总之：别写）：1 << 32（int）是 UB。
  • << 优先级低于 + -：1 << 2 + 3 是 1 << 5；写宏时全加括号。
  • 优先级速记：!~++ → 乘除 → 加减 → 移位 → 关系 → 相等 → & → ^ → | → && → || → 三目 → 赋值。
  • i = i++、同一表达式多次修改同一变量均为未定义行为，考试别玩花。

逻辑 vs 短路

  • && / || 有短路特性：p && *p 是合法的空指针防护写法。
  • ! 优先级高于算术运算：!a + b 是 (!a) + b。
CH.03

控制流与函数

函数基础 ★高频

  • C 只有值传递：传数组/指针可改内容，传结构体是拷贝（大结构体传 const T*）。（结构体 = 把几个不同类型的变量打包成一个整体，见 CH.06；指针 = 存"变量地址"的变量，见 CH.04；const T* = 只许读不许通过它改的指针，见 CH.07。初次学可先只记结论）
  • 未写返回类型的函数默认 int（C89）；C99 起必须显式写。
  • 局部变量不初始化是随机值；static 局部变量自动清零且只初始化一次（static 在这里 = "让局部变量活过函数调用、常驻内存"，完整讲法见 CH.07）。
int counter(void){
    static int n = 0;   // 只初始化一次，函数退出后仍存在。存 .data/.bss = 全局变量住的静态区，见 CH.08
    return ++n;          // 连续调用返回 1,2,3...
}

switch 细节 易错

  • case 必须是整型常量表达式；忘写 break 会贯穿（fall-through）。
  • case 值不能重复；default 可放任意位置。

递归 vs 迭代

  • 递归每层压栈，嵌入式栈空间小（常 1~8KB），深度递归可能栈溢出；面试常问阶乘/斐波那契两种写法。
  • 函数调用开销：压栈参数、返回地址、保存寄存器——资源受限场合循环优于递归。
CH.04

指针（核心）

const 与指针 ★高频·必背

const int *p;        // 指向常量的指针：*p 不可改，p 可改（左定值）
int *const p;        // 常量指针：p 不可改，*p 可改（右定址）
const int *const p;  // 都不可改
/* 记忆：const 在 * 左边 → 数据只读；在 * 右边 → 指针只读 */

指针运算 ★高频

  • p + n 前进 n × sizeof(*p) 字节——按元素移动而非按字节。
  • 两指针相减 = 相差的元素个数；指针比较/相减仅对同一数组内有意义。
  • a[i] 完全等价于 *(a+i)，所以 i[a] 也合法（面试冷知识）。
  • void* 无类型指针：不能解引用、不能算术（GCC 扩展按 1 字节），malloc 返回它，作万能参数。

多级指针与函数指针 ★高频

int **pp;                     // 二级指针：修改调用者的指针本身（如 my_malloc(&p)）

int (*fp)(int, int);          // 函数指针：指向"参数(int,int)返回int"的函数
int (*arr[10])(void);         // 函数指针数组（跳转表）
int (*(f(int)))(void);        // 返回函数指针的函数
fp = add; int r = fp(1,2);    // 调用；回调函数、中断向量表、驱动 ops 都靠它

读复杂声明的口诀：从变量名出发，右结合优先，遇括号回头。int (*(*p)[5])(void) = p 是指针 → 指向「5 个函数指针的数组」→ 每个函数返回 int。

手撕代码：指针四连 ★高频·必默写

// 1) 交换两变量的值——必须传二级地址，否则改的是副本
void swap(int *a, int *b){ int t=*a; *a=*b; *b=t; }

// 2) 修改调用者的指针本身 → 二级指针（如分配链表头）。malloc = 运行时向"堆"申请内存，见 CH.08
void alloc(int **pp){ *pp = (int*)malloc(sizeof(int)*10); }

// 3) 手写 memcpy：返回 dst 支持链式，逐字节拷贝
void *my_memcpy(void *dst, const void *src, size_t n){
    char *d = dst; const char *s = src;
    while (n--) *d++ = *s++;
    return dst;
}

// 4) 判断 1 出现的次数 / 反转字符串等也常靠双指针
易错：memcpy 源目不可重叠（重叠用 memmove，先判方向再拷）；swap 传 int 而非 int* 则无效——这是值传递最经典的坑。

野指针与悬空指针 易错

  • 野指针：未初始化就使用。防御：定义时 = NULL，用完置 NULL，解引用前判空。
  • 悬空指针：指向已释放的堆内存或已出作用域的栈变量（绝不能 return 局部变量的地址）。
  • NULL 与 '\0' 与 0：空指针 / 字符零 / 整型零，语义不同。
CH.05

数组与字符串

数组与指针的区别 ★高频

数组 char a[10]指针 char *p
本质一块连续内存（左值不可改地址）存地址的变量（p++ 合法）
sizeof10（定义作用域内）4/8
作函数参数退化为指针，丢失长度信息 → 必须额外传 size
char *s = "abc";    // 字符串字面量存只读段，s[0]='x' 是未定义行为（可能硬件异常）
char a[] = "abc";    // 拷贝到栈上，可修改

字符串函数考点 ★高频

  • strlen 数到 '\0' 为止、不含 '\0'，参数必须是以 '\0' 结尾的串。
  • strcpy(dst, src) 不检查 dst 大小 → 缓冲区溢出；安全版本 strncpy（注意可能不补 '\0'）。
  • strcmp 返回 <0 / 0 / >0；不能用 == 比较字符串内容（那是比较地址）。
  • 手写 strcpy 是面试保留节目：返回 dst 支持链式、逐字节拷到 '\0'。
  • 经典一行：while (*dst++ = *src++);——赋值表达式非零则继续，拷完 '\0' 退出。

多维数组

  • int m[3][4] 按行存储；m[i][j] 地址 = 基址 + (i×4+j)×4。
  • 传参必须给出列数：void f(int a[][4], int rows);
CH.06

结构体·联合体·内存对齐

内存对齐 ★高频·必考

规则：① 每个成员的偏移必须是「min(自身对齐, pack值)」的倍数，不足则填充；② 总大小是最大对齐值的倍数。

struct S { char a; int b; short c; };
// a:偏移0(1B) + 填3B | b:偏移4(4B) | c:偏移8(2B) + 填2B
// sizeof(S) == 12，而不是 1+4+2 = 7

// 省内存技巧：成员按大小降序排列
struct T { int b; short c; char a; };  // sizeof(T) == 8

#pragma pack(1)   // 取消填充：协议头/寄存器映射常用；代价是可能非对齐访问（Cortex-M0 会 HardFault）

联合体 union ★高频

  • 所有成员共享同一块内存，同一时刻只有一个有效；大小 = 最大成员（对齐后）。
  • 用途：判断大小端、节省内存（互斥字段）、原始字节访问（拆包）。
/* 判断大小端——笔试标准答案 */
int is_little_endian(void){
    union { int i; char c; } u = { .i = 1 };
    return u.c == 1;    // 低地址存了低位字节 → 小端
}

位域 bit-field

struct { uint32_t en:1, mode:3, rsv:28; } ctl;  // 按位打包寄存器配置
  • 位域分配顺序（从低位还是高位起）是实现定义的 → 跨平台协议解析别用位域，改用移位掩码。

结构体其他考点

  • struct 赋值是整体拷贝；传参用 const struct T* 避免拷贝（小结构体如 4 字节可直接传值）。
  • -> 用于指针，. 用于实体：p->member ≡ (*p).member；优先级最高。
  • 柔性数组 int data[];（C99，必须是最后一个成员，sizeof 不计入）配合 malloc 做变长包。
  • typedef 起别名简化声明：typedef struct Node Node; struct Node { int v; Node *next; };

offsetof 与自引用结构体 ★高频

// offsetof 算某成员偏移量（<stddef.h>），验证对齐结果常用
#define OFFSETOF(type, m)  ((size_t)&((type*)0)->m)   // 经典手写版：把 0 当结构体首地址

// 自引用结构体：链表/树节点的基础，指针成员指向同类型
typedef struct Node {
    int data;
    struct Node *next;   // 必须写 struct Node，不能只写 Node（类型未定义完）
} Node;

// 嵌入式常见：用 struct 封装外设的一组寄存器 + 操作函数指针（面向对象风格）
struct device_ops { int (*init)(void); int (*read)(uint8_t*); };  // Linux 驱动模型核心
追问：结构体能不能比较？→ C 语言没有结构体 == 运算符（因有填充字节，逐字节比也不可靠），必须逐成员比较或 memcmp 慎用。
CH.07

关键字：static / const / volatile

static ★高频·必考

修饰对象效果存储位置
局部变量生命周期延长到程序结束，只初始化一次.data / .bss（静态区）
全局变量作用域限制在本文件（内部链接），防命名冲突.data / .bss
函数仅本文件可见——模块封装的基本手段—

追问常考：static 全局变量与普通全局变量的区别？→ 作用域（链接属性）不同，存储位置相同。

volatile ★高频·嵌入式灵魂

  • 含义：该变量可能在程序控制流之外被改变，禁止编译器优化缓存，每次访问都必须真正读写内存。
  • 三个必用场景：① 硬件寄存器映射；② 中断与主循环共享的标志变量；③ 多线程/RTOS 共享变量（多线程还需配合原子操作/锁，volatile 不保证原子性）。
// 不加 volatile：编译器可能把 while 里的读取优化成只读一次 → 死循环
volatile int flag = 0;             // 中断里置 1，主循环轮询
void poll(void){ while (!flag) ; }

// 组合考法：const volatile —— 只读的硬件状态寄存器（软件不许写，硬件会变）
const volatile uint32_t *status = (uint32_t *)0x40021010;

const ★高频

  • 作用：只读保护（编译期查错）、给编译器优化提示、修饰指针参数表明不改数据。
  • const vs #define：const 有类型检查、占内存（或 ROM）、有作用域；宏无类型、纯文本替换。
  • const 全局数组放 Flash/ROM（如字库、查找表），省 RAM——嵌入式必知。
  • 强制去 const（(int*)&cv 后修改）是未定义行为。

extern / register / inline / restrict

  • extern：声明别处定义的全局变量/函数（声明≠定义，不分配存储）；extern "C" 用于 C++ 调 C 时关闭名字改编。
  • register：建议放寄存器；现代编译器基本忽略，且不能取地址。
  • inline：建议内联展开省调用开销；C99 语义下通常仍需一处 extern 定义。
  • restrict（C99）：承诺指针是访问该数据的唯一途径，允许更激进优化（memcpy 原型里有）。
CH.08

内存管理

内存分区 ★高频·必背

区域存放内容特点
栈区 stack局部变量、函数参数、返回地址自动分配释放，速度快；嵌入式中很小（溢出 → HardFault）
堆区 heapmalloc/calloc/realloc 的内存手动管理，灵活；有碎片和泄漏风险
.data已初始化的全局/静态变量启动代码从 Flash 拷到 RAM
.bss未初始化（或=0）的全局/静态变量启动时清零，不占固件体积
常量区 rodata字符串字面量、const 全局放 Flash，只读
代码区 text机器指令只读、可共享

追问：栈和堆的区别？→ 分配方式（自动/手动）、速度、大小限制、增长方向（相向而生）、碎片问题。

malloc 系列与陷阱 ★高频

int *p = (int *)malloc(10 * sizeof(int));
if (p == NULL) { /* 必须判空！ */ }
/* ...使用... */
free(p); p = NULL;   // 置空防悬空指针；free(NULL) 安全；重复 free 是严重错误
  • malloc 不清零、calloc 清零、realloc 扩缩容（可能整体搬家，必须接收返回值）。
  • 内存泄漏：malloc 后丢失指针 / 忘记 free；检测思路：封装计数、valgrind。
  • 嵌入式观点（面试加分）：实时系统通常避免动态分配——不确定何时失败、产生碎片；改用静态内存池 / RTOS 的固定块分配。

realloc 与内存池 ★高频

// realloc 陷阱：失败返回 NULL 但原块仍在，不能直接覆盖原指针！
int *tmp = (int*)realloc(p, new_size);
if (tmp) p = tmp; else { /* 失败，p 仍可用 */ }

// 嵌入式替代动态分配：静态内存池（固定块，无碎片，O(1) 分配）
static uint8_t pool[POOL_N][BLOCK_SZ];   // 启动时一次性占好 RAM
static bool used[POOL_N];                // 位图管理空闲块

内存泄漏定位

  • 四种典型泄漏：① 分配后指针被覆盖；② 异常分支提前 return 未 free；③ 只 free 了结构体没 free 其指针成员；④ realloc 失败覆盖了原指针。
  • 工具：Linux valgrind；嵌入式无 OS 时用「分配/释放配对计数宏」或链接器统计 .bss 用量。
  • 排查思路：先确定是泄漏（占用持续增长）还是越界（随机崩溃），前者查 free，后者查边界与栈深。

经典错误清单 易错

  • 返回栈上局部变量的地址（出函数即失效）。
  • 数组越界写：int a[8]; a[8]=1; 可能踩坏相邻变量/返回地址。
  • free 后继续使用（use-after-free）；两个指针指向同一块内存各自 free（double free）。
  • memcpy 源目重叠应用 memmove；calloc(n,size) 参数顺序与 malloc 不同。
CH.09

数据结构：链表·栈·队列·树

单链表手撕代码 ★高频·必默写

typedef struct Node { int data; struct Node *next; } Node;

// 反转链表——笔试出现率第一，三种写法都要会
Node *reverse(Node *head){
    Node *prev = NULL, *cur = head;
    while (cur) {
        Node *next = cur->next;  // 先存后继，防断链
        cur->next = prev;        // 翻转指向
        prev = cur; cur = next;  // 双指针前进
    }
    return prev;                 // prev 是新头
}

// 合并两个有序链表（GeeksforGeeks 高频题）
Node *merge(Node *a, Node *b){
    Node dummy = {0, NULL}, *tail = &dummy;   // 哑结点省去判空头
    while (a && b) {
        if (a->data <= b->data) { tail->next = a; a = a->next; }
        else                    { tail->next = b; b = b->next; }
        tail = tail->next;
    }
    tail->next = a ? a : b;                   // 接上剩余段
    return dummy.next;
}

// 快慢指针找中点 / 判环（Floyd 判圈算法）
int has_cycle(Node *head){
    Node *slow = head, *fast = head;
    while (fast && fast->next) {
        slow = slow->next; fast = fast->next->next;
        if (slow == fast) return 1;   // 相遇即有环
    }
    return 0;
}

// 删除节点通用套路：操作前驱 pre，使 pre->next 跳过目标；删除头节点单独处理或用二级指针
void del(Node **head, int val){
    Node **pp = head;                          // 二级指针统一处理头节点
    while (*pp) {
        if ((*pp)->data == val) {
            Node *dead = *pp;
            *pp = dead->next; free(dead); return;
        }
        pp = &(*pp)->next;
    }
}
易错：反转时不先保存 next 就改 cur->next → 链表断裂；删除节点直接操作当前节点而非前驱 → 头节点删不掉；遍历循环条件漏判 fast->next → 空指针解引用。

链表 vs 数组 ★高频

数组单链表
随机访问 a[i]O(1)O(n)
头部插入/删除O(n) 需搬移O(1)
内存连续、需预知大小离散、按需分配、额外指针开销
缓存友好性好（局部性）差（节点分散）
  • 变种：双向链表（含 prev，删除 O(1)）、循环链表（尾接回，RTOS 任务列表常用）。
  • 嵌入式场景：链表节点从静态内存池取，避免运行期 malloc 碎片。

栈与队列 ★高频

  • 栈（LIFO）：数组实现只需 top 下标；push 前判满（top == N-1）、pop 前判空——两个边界判断必写。
  • 队列（FIFO）：循环队列用数组最优，浪费一个格区分空/满，或用 size 计数。
// 循环队列核心三式（笔试常考"队满条件"）
入队: rear = (rear + 1) % N;
出队: front = (front + 1) % N;
队满: (rear + 1) % N == front;   // 队空: rear == front

// 用两个栈实现队列 / 用队列实现栈：经典设计题
  • 应用考点：括号匹配、表达式求值（中缀转后缀）、函数调用栈原理、递归改迭代都要栈。
  • 嵌入式场景：中断数据缓冲用环形缓冲区（ring buffer）——就是循环队列，UART DMA 接收必备。

树 ★高频

typedef struct TreeNode { int val; struct TreeNode *l, *r; } TNode;

// 三种深度遍历——递归版必须秒写；层序遍历用队列
void inorder(TNode *t){          // 中序：左根右（BST 得到有序序列！）
    if (!t) return;
    inorder(t->l); printf("%d ", t->val); inorder(t->r);
}
int depth(TNode *t){              // 求树深：递归三行
    if (!t) return 0;
    int l = depth(t->l), r = depth(t->r);
    return (l > r ? l : r) + 1;
}
  • 二叉搜索树 BST：左 < 根 < 右，查找/插入平均 O(log n)，退化成链表时 O(n)。
  • BST 中序遍历 = 升序输出——高频结论题。
  • 先序+中序可唯一还原二叉树（重建题）；平衡因子、AVL 概念了解即可。
CH.10

算法：排序·查找·复杂度

必会排序手撕 ★高频·必默写

// 冒泡：每轮把最大值"冒"到末尾；加 swapped 标志可提前退出
void bubble(int a[], int n){
    for (int i = 0; i < n-1; i++) {
        int swapped = 0;
        for (int j = 0; j < n-1-i; j++)
            if (a[j] > a[j+1]) { int t=a[j]; a[j]=a[j+1]; a[j+1]=t; swapped=1; }
        if (!swapped) break;              // 本轮无交换 → 已有序
    }
}

// 插入排序：像整理扑克牌；近乎有序时接近 O(n)，小数组首选
void insert(int a[], int n){
    for (int i = 1; i < n; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j+1] = a[j]; j--; }
        a[j+1] = key;
    }
}

// 快排：分治+partition，平均 O(nlogn)，面试最常考"手写快排"
void quick(int a[], int lo, int hi){
    if (lo >= hi) return;
    int pivot = a[hi], i = lo;            // 取末元素为基准
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) { int t=a[i]; a[i]=a[j]; a[j]=t; i++; }
    int t=a[i]; a[i]=a[hi]; a[hi]=t;       // 基准归位
    quick(a, lo, i-1); quick(a, i+1, hi);
}

// 选择排序：每轮选最小的放到前面，交换次数最少 O(n)——Flash/功耗敏感场合有用

排序对比表 ★高频·必背

算法平均最坏空间稳定备注
冒泡O(n²)O(n²)O(1)✔加 swapped 优化后，有序数据 O(n)
插入O(n²)O(n²)O(1)✔基本有序时最快
选择O(n²)O(n²)O(1)✘任何情况都 O(n²)
快速O(nlogn)O(n²)O(logn)✘最坏发生在已有序+固定基准
归并O(nlogn)O(nlogn)O(n)✔稳定且无最坏退化，链表归并可 O(1) 空间
堆O(nlogn)O(nlogn)O(1)✘Top-K 问题首选
  • 「稳定」= 相等元素保持原相对顺序；口诀：不稳定的是「快些选一堆」（快排、希尔、选择、堆）。
  • 追问：为什么嵌入式很少用快排递归版？→ 栈深不可控，实时系统改用插入/归并或限制递归深度。

查找 ★高频

// 二分查找——边界写法是重灾区，必须一次写对
int bsearch(int a[], int n, int key){
    int lo = 0, hi = n - 1;
    while (lo <= hi) {                       // 闭区间用 <=
        int mid = lo + (hi - lo) / 2;        // 防 (lo+hi) 溢出！
        if (a[mid] == key) return mid;
        else if (a[mid] < key) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
  • 二分三大易错：循环条件 <= vs <、区间收缩 ±1、mid 溢出写法。
  • 变体：找第一个 ≥ key 的位置（lower_bound）、旋转数组查找——大厂笔试常客。
  • 顺序查找 O(n) 无序可用；二分 O(log n) 必须有序；哈希 O(1) 均摊但费内存。

高频算法小题 ★高频

  • 斐波那契：递归 O(2ⁿ) 会重复计算 → 迭代 O(n) 或记忆化；笔试必写两种并说复杂度。
  • 字符串反转：双指针首尾交换到相遇，O(n)/O(1)。
  • 数组去重/找唯一数：全员异或——成对的抵消，剩下的就是答案（位运算+数组经典结合）。
  • 判断回文：双指针从两端向中间。
  • Top-K：维护 K 大小的堆或快速选择。
  • 大 O 速判：单层循环 O(n)、嵌套 O(n²)、每轮减半 O(log n)、排序后处理 O(nlogn)。
答题模板：先说思路 → 说复杂度 → 写代码 → 主动说边界（空输入、单元素、重复值）。面试官最看重的是边界处理意识。

预处理与多文件编程

宏定义 ★高频·必考

#define SQUARE(x) ((x) * (x))   // 参数和整体都加括号！
#define MAX(a,b)  ((a) > (b) ? (a) : (b))

// 陷阱演示：
SQUARE(a + b)   // 不加括号 → a + b*a + b，错
SQUARE(i++)     // 即使加括号，i 也被自增两次 → 带副作用的实参是宏的天敌
  • 宏 vs 函数：宏是编译前文本替换，无类型检查、无调用开销、代码膨胀、可传类型/表达式作参数；函数有类型检查、有调用开销。
  • # 把参数变字符串（stringify），## 拼接记号：#define REG(n) GPIO##n → REG(A) 展开为 GPIOA。
  • do{...}while(0) 包裹多语句宏，保证在 if/else 中语法正确。

头文件与条件编译 ★高频

/* include guard：防止重复包含——每个头文件的标配 */
#ifndef __UART_H__
#define __UART_H__
/* 头文件只放：声明（函数原型、extern 变量、类型、宏），不放定义 */
#endif

#ifdef DEBUG
    printf("dbg: x=%d\n", x);
#endif
  • #include <file> 搜系统路径，"file" 先搜当前目录。
  • 预处理四步：展开宏 → 处理条件编译 → 插入头文件 → 删除注释；之后才是编译、汇编、链接。
  • #error / #pragma / 预定义宏 __FILE__ __LINE__ __func__ __DATE__（日志和断言常用）。
  • 重复定义 vs 重复声明：链接期重复定义报 multiple definition；声明可以多次。

嵌入式专项考点

寄存器操作 ★高频·必背

// 绝对地址访问的标准写法：volatile 防优化 + 强制类型转换 + 解引用
#define REG32(addr)  (*(volatile uint32_t *)(addr))

REG32(0x40021018) |=  (1U << 3);    // 置位（读-改-写）
REG32(0x40021018) &= ~(1U << 3);    // 清零
while (REG32(UART_SR) & (1U << 7)) ; // 轮询等待标志位

追问「读-改-写」的风险：多中断/多核并发时非原子 → 关中断或用位带（bit-band）操作。

大小端 ★高频

  • 小端：低字节存低地址（x86、ARM 默认）；大端：高字节存低地址（网络字节序、部分 PowerPC）。
  • 0x12345678 在小端内存中依次是 78 56 34 12。
  • 判断方法：union 法（见 CH.06）或 *(char*)&x 法；转换：htons/htonl/ntohs/ntohl。

中断与 C ★高频

  • ISR 编写准则：短小（只置标志/存数据，处理放主循环）、不调用 printf/malloc 等非可重入函数、不能返回值和带参数（硬件决定）、共享变量必须 volatile。
  • 可重入函数：不依赖静态/全局可变状态的函数才安全被中断打断后再次进入。
  • 中断里改了标志、主循环 while 死等却不加 volatile → 编译器 -O2 把标志缓存进寄存器 → 死循环。这是最经典的嵌入式 C 综合题。
  • C 与汇编混合：启动文件（startup.s）设栈、拷贝 .data、清 .bss，再跳 main；ISR 入口保存现场。
